# Форма ответа пользователя в диалоге

`face/widgets/aiDialogueForm/AiDialogueForm/AiDialogueInput.tsx` — клиентская форма с вкладками
«Реплика» и «Действие», диктовкой, проверкой текста и отправкой сообщения. Оба текста независимы;
достаточно заполнить хотя бы один. Письменное описание пользователя имеет приоритет над Frame.pdf.

## Интерфейс

- Сверху — общий `Switcher` и кнопка «Уйти от разговора» с `ExitButtonIcon`.
- Одно обычное `textarea` без рамки показывает активную часть; содержимое и выделение второй вкладки сохраняются.
  Высота обновляется по `scrollHeight` при вводе, диктовке, переключении и изменении ширины.
- Placeholder реплики — `Hi, how’s it going?`, действия — `I opened the door`.
- Ниже текста — сообщение о технической ошибке и результаты проверки: нумерованные критические ошибки
  с заголовком, исходным фрагментом и пояснением; рекомендации — отдельный серый блок с примером.
  Markdown отображается через существующий `StyledMarkdown`, без исполнения HTML из ответа модели.
- Внизу — статус, «Диктовать» / «Завершить» / заблокированное «Распознавание» и «Проверить» / «Отправить».
  Доступная кнопка проверки тёмная, отправка и остановка записи — акцентные.
- На мобильной ширине статус занимает отдельную строку, кнопки остаются справа под ним.

Для пустого поля статус содержит «Напечатайте [TextSmallButtonIcon] или продиктуйте
[MicSmallButtonIcon] реплику/действие». Другие состояния:

| Состояние активной части | Статус |
|---|---|
| Новый или изменённый текст | Отправьте на проверку |
| Получение разрешения/подключение микрофона | Подключаю микрофон… |
| Запись после ready | Слушаю… |
| Остановка до окончательного результата | Завершаю распознавание… |
| REST-проверка | Идёт проверка текста… |
| Проверены критические ошибки | [LockSmallButtonIcon] Исправьте N ошибок, чтобы отправить ответ |
| Активная часть готова, другая содержит проверенные ошибки | Текст действия/реплики содержит ошибки. |
| Активная часть готова, другая ещё не проверена | Проверьте текст действия/реплики. |
| Все заполненные части готовы | Ответ можно отправить. |

Количество ошибок склоняется по-русски. Перед ready статус подключения помогает не начинать речь раньше записи.

## Состояние и проверка

`fn/AiDialogueDraftController.ts` управляет логикой независимо от React. `useAiDialogueDraft` подключает
его через `useSyncExternalStore` и передаёт зависимости API, микрофона и отправки.
Для каждой части хранятся текст, версия, диапазон курсора, результат проверки с версией,
признак запроса и техническая ошибка. Один экземпляр контроллера соответствует одному dialogueId.

«Проверить» отправляет **только активную часть** через
`AiDialogueService.checkUserMessageText` → Repository/API → сгенерированный
`aiDialogueControllerCheckAiDialogueUserMessageText`. Языки и историю клиент не задаёт.
Внешний серверный контракт допускает обе части; клиент намеренно проверяет каждую отдельно,
чтобы состояние вкладок соответствовало пользовательскому сценарию. Результат для второй,
непереданной части не помечает её как проверенную.
Контракт сервера: [`aiDialogueMessageCheck.md`](aiDialogueMessageCheck.md).

Проверяемое поле серое и readOnly. Можно переключиться на другую вкладку и работать с ней,
включая отдельную проверку. Запоздалый результат принимается только для того же запроса и версии.
Сбой, отмена и повреждённый HTTP-ответ не превращаются в успешное отсутствие ошибок.
При ошибке показано «Не удалось проверить текст.», повторная проверка доступна.

Любая правка изменяет версию, даже если потом вернуть прежнюю строку. Предыдущие замечания
сохраняются с подписью «Замечания к предыдущей версии текста», но отправку не разрешают.
Повторная проверка очищает старый результат. Рекомендации отправку не блокируют.
Поля ограничены 4000 UTF-16 единицами на клиенте; сервер также проверяет свой лимит.

## Кнопка отправки

Если активная непустая часть проверена и не имеет critical, видна «Отправить».
Она включена только когда **каждая непустая часть** проверена в своей текущей версии и не содержит critical,
нет диктовки, проверок, отправки или генерации NPC. Пустая вторая часть допустима.
Иначе на активной вкладке видна «Проверить»; она отключена для пустого поля и во время записи/запроса.

Enter выполняет действие текущей правой кнопки, Shift+Enter вставляет перенос; ввод с IME не отправляет текст.
Нельзя отправить непроверенный текст через клавиатуру в обход кнопки.
Отправка вызывает существующий `useAiDialogueSendMessage`: speech перед action, пустые части исключаются.
Черновики очищаются только при успешном POST; ошибка сохраняет тексты и актуальные проверки.
Повторный клик во время отправки не создаёт второй запрос.

«Уйти от разговора» отправляет `userAvoidsNPC` без грамматической проверки, отменяя текущий микрофон/проверки.
Это уход от NPC, а не удаление диалога. Во время генерации NPC и отправки форма заблокирована.
REST `/messages` по-прежнему не проверяет наличие грамматического подтверждения на сервере.

## Диктовка и выделение

`entities/aiDialogue/dictation/openAiDialogueDictation.ts` открывает браузерную запись и
`WS(S) /api/ai-dialogue/:id/dictation` на текущем origin. Авторизационная cookie передаётся браузером.
MediaRecorder выбирает WebM/Opus или Ogg/Opus; запись начинается
после серверного ready и выдаёт фрагменты каждые 200 мс. Если эти контейнеры недоступны,
используется AudioContext/AudioWorklet: моно PCM16LE с частотой контекста (48 кГц).
MP4 не передаётся в потоковый API: он указан у Soniox только для файловой транскрибации.
Форматы: [Soniox real-time transcription](https://soniox.com/docs/stt/rt/real-time-transcription#audio-formats).
Worklet выдаёт порции по 2048 сэмплов и сбрасывает короткий хвост перед подтверждением stop.
Граф не проигрывает записываемый голос в динамиках; AudioContext закрывается при завершении или отмене.
Серверные правила: [`aiDialogueDictation.md`](aiDialogueDictation.md).

Перед записью фиксируются исходный текст и selectionStart/selectionEnd. Для pointer-нажатия
«Диктовать» предотвращается переход фокуса на кнопку; при клавиатурном запуске используется
сохранённое выделение. Во время распознавания textarea остаётся readOnly и показывает
выделенный вставляемый фрагмент. Префикс и суффикс исходного текста не меняются,
выделенные слова заменяются диктовкой; дополнительные пробелы автоматически не добавляются.
Пустая диктовка не удаляет исходное выделение.

partial заменяет предварительный хвост; final добавляется к подтверждённой части без новых пробелов.
done заменяет вставку полным финальным текстом один раз. Переключение вкладок и проверка во время
диктовки запрещены, чтобы запись не попала в другое поле.

«Завершить» останавливает recorder. Микрофон освобождается при событии stop, а серверный stop
отправляется после последнего dataavailable и всех последовательных Blob → ArrayBuffer преобразований.
До done поле серое, проверка и повторная диктовка заблокированы.
При нажатии «Завершить» до подключения микрофона текущая попытка отменяется.

При сетевом сбое сохраняется подтверждённая часть и отбрасывается предварительный хвост;
если подтверждённого текста не было, восстанавливается исходный текст с выделенными словами.
Превышение 4000 символов останавливает запись без обрезания окружающего текста.
Ошибки доступа к микрофону, отсутствия устройства и соединения отображаются в форме.
Автоматического переподключения и повтора аудио нет.

Клиент ограничивает очередь аудио 1 МиБ / 64 фрагментами, WebSocket-буфер 512 КиБ;
большие Blob отправляются частями по 64 КиБ. Таймаут подключения — 30 с, записи — 5 мин,
ожидания завершения — 60 с. Сервер применяет собственные ограничения.

При смене dialogueId/размонтировании отменяются REST-проверки, recorder, дорожки микрофона и WebSocket,
очищаются таймеры; позднее разрешение getUserMedia также освобождает полученные дорожки.
Возвраты старых операций игнорируются. `useAiDialogueSendMessage` не добавляет запоздалый POST-ответ
прежней страницы в общий стор после навигации.

## Основные файлы и проверки

- `face/widgets/aiDialogueForm/AiDialogueForm/AiDialogueInput.tsx` — редактор и смена экземпляра формы по dialogueId.
- `AiDialogueDraftControls.tsx`, `AiDialogueDraftFeedback.tsx` рядом — кнопки, статусы и замечания.
- `fn/AiDialogueDraftController.ts`, `fn/aiDialogueDraftState.ts` — состояние, версии и правила готовности.
- `fn/useDraftTextarea.ts` — автовысота и видимое выделение диктовки.
- `face/entities/aiDialogue/messageCheck/userMessageCheckTypes.ts` — типы независимые от Orval.
- `face/entities/aiDialogue/dictation/openAiDialogueDictation.ts` — браузерный транспорт записи.
- `createDictationRecorder.ts` рядом и `face/public/audio/ai-dialogue-pcm-worklet.js` — выбор формата и PCM fallback.
- `face/tests/aiDialogueDraft.test.ts`, `aiDialogueDictation.test.ts`, `aiDialogueMessageCheck.test.ts` — изолированные тесты.
- `face/e2e/aiDialogueForm.spec.ts` — форма в настоящем браузере с подменой API/SSE/микрофона/WebSocket.

```bash
cd face
npm run test:ai-dialogue
npx playwright test e2e/aiDialogueForm.spec.ts --project=chromium --workers=1
```

Для Playwright нужен установленный браузер соответствующей версии. Тесты не вызывают платные LLM/Soniox,
не используют настоящую запись микрофона и не изменяют БД. Они проверяют вкладки, ошибки второй части,
сброс проверок при изменении, отправку, вставку в выделение, readOnly/статусы/автовысоту и мобильную ширину.
Качество реального распознавания и разрешения микрофона в целевых браузерах проверяются отдельно.
