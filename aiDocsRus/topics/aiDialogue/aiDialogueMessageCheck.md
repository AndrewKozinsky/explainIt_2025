# Проверка черновика реплики и действия

## Назначение

`POST /api/ai-dialogue/:id/check-message` проверяет грамматику, лексику, написание и стиль
черновика до отправки в ролевой диалог. Пользователь может заполнить **реплику и/или действие**:
оба поля одновременно не обязательны. Заполненные поля проверяются одним вызовом LLM,
результаты разделены по полям.

Это самостоятельная проверка: она не сохраняет черновик, не меняет историю, настройки или summary,
не публикует SSE-события и не запускает ответ NPC. Проверка может выполняться независимо от генерации хода.
Существующий `POST .../messages` не требует подтверждения проверки. Блокировка кнопки отправки —
исключительно ответственность будущего клиента.

## Запрос

Требуется авторизация (`CheckSessionCookieGuard`) и владение диалогом.

```http
POST /api/ai-dialogue/12/check-message
Content-Type: application/json
```

```json
{
  "speech": "Hey girls! There is a очередь.",
  "action": "I opened the door."
}
```

Оба свойства необязательны, принимают строку или `null`; отсутствие, `null`, пустая строка
и строка из пробелов означают незаполненное поле. Внешние пробелы удаляются, внутренние переносы
сохраняются во входе LLM. Если оба поля пусты — `400 AI_DIALOGUE_CHECK_TEXT_REQUIRED`.
Ограничение каждого поля — 4000 символов после удаления внешних пробелов.
Неверные типы, превышение лимита и неизвестные свойства отклоняются глобальным ValidationPipe.

Языки и контекст клиент не передаёт:

- `source_language_code` диалога — изучаемый язык проверяемого текста и исправленных примеров;
- `target_language_code` — язык заголовков и пояснений;
- текущая сцена, последние события и сводка извлекаются сервером после проверки владельца.

## Ответ

`200 OK`, `Cache-Control: private, no-store`:

```json
{
  "speech": {
    "critical": [
      {
        "title": "Слово на русском языке",
        "sentenceMarkdown": "There is a **очередь**.",
        "explanationMarkdown": "«Очередь» по-английски — **queue**."
      }
    ],
    "suggestions": [
      {
        "explanationMarkdown": "После обращения **Hey** нужна запятая.",
        "example": "Hey, girls!"
      }
    ]
  },
  "action": {
    "critical": [],
    "suggestions": []
  }
}
```

Оба поля и оба массива присутствуют всегда. Для незаполненного поля массивы пусты;
это не означает, что его будущий текст уже проверен. `critical` — ошибки, требующие исправления,
`suggestions` — необязательные рекомендации. Заголовок и выделенное исходное предложение есть
только у критической ошибки; у рекомендации — пояснение и исправленный пример.
Markdown ограничен однострочным inline-форматом. Пример рекомендации — обычный текст.

Критическими считаются реальные грамматические, орфографические и лексические ошибки,
в том числе непереведённые вставки родного языка. Собственные имена и устоявшиеся заимствования
не считаются ошибками автоматически. Незначительная пунктуация, грамматически допустимый,
но неестественный порядок слов и необязательные улучшения стиля — рекомендации.
Корректные разговорные фрагменты, сокращения и уместные описания действий не требуется
переписывать в полные формальные предложения. Ограничение CEFR на проверку не распространяется.

Клиент должен связать результат с точным снимком обоих отправленных полей. После любой правки
соответствующее поле требует новой проверки; запоздавший ответ для старого снимка не подтверждает новый текст.
Для интерфейса из макета отправка доступна, когда каждое заполненное поле проверено и не имеет `critical`.
Техническая ошибка запроса не должна отображаться как успешная проверка без ошибок.
Текущий клиент в этом этапе не изменён.

## Контекст и LLM

Маршрут → `CommandBus` → `CheckAiDialogueUserMessageHandler`:

1. Проверка существования и владельца диалога.
2. Проверка наличия хотя бы одного непустого поля.
3. Загрузка последних 8 сообщений в хронологическом порядке и последнего `sceneUpdate`
   отдельным запросом (сцена может быть старше этих сообщений).
4. Из каждого события передаётся до 2000 символов видимого текста суммарно, до 8 элементов actions,
   имя NPC — до 200 символов. Переводы, карты слов и визуальные метаданные исключаются.
   Из последнего блока summary передаётся хвост history до 3000 символов.
5. Один вызов `LlmAdapterService.generate`, `responseFormat: 'text'`, таймаут 45 секунд,
   стандартная модель адаптера (`DEFAULT_FLASH_AI_MODEL`). Автоматических повторов нет.
6. Строгий разбор полного ответа. Некорректный результат не сохраняется и не выдаётся как успешная проверка.

Системный промпт отделён от JSON с данными контекста/черновика. Тексты диалога и пользователя
явно трактуются как данные, а не инструкции. Проверяющий не продолжает сцену и не исправляет историю.
Оценка языка и классификация ошибок выполняются LLM; тесты с подменой провайдера не доказывают
лингвистическое качество реальной модели.

## Компактный формат ответа модели

Внешний REST-ответ остаётся типизированным JSON. Для генерации используется текст без JSON-ключей
для каждой ошибки, с фиксированным порядком значений:

```text
speech
critical
Слово на русском языке
There is a **очередь**.
«Очередь» по-английски — **queue**.
suggestion
После обращения **Hey** нужна запятая.
Hey, girls!
action
ok
end
```

Секции идут строго `speech`, `action`. В секции либо единственный `ok`, либо записи:

- `critical` + 3 непустые строки: заголовок, исходный фрагмент с выделением, объяснение;
- `suggestion` + 2 непустые строки: объяснение, пример.

Последняя строка — `end`; каждая строка содержимого занимает одну физическую строку.
Переносы исходного предложения при цитировании заменяются пробелами. Пустые строки, JSON,
code fences, неизвестные маркеры, смешение `ok` с ошибками и посторонний текст не допускаются.
Маркеры, встретившиеся внутри фиксированных позиций содержимого, являются обычным текстом.
Лимиты: до 12 замечаний на поле, до 8000 символов на строку содержимого, до 64000 символов на ответ.
Промпт требует отдавать критические ошибки в приоритете при достижении лимита.
Замечания к незаполненному полю также делают весь результат некорректным.

Маркеры `ok` и `end` позволяют отличить явное отсутствие ошибок от пустого или оборванного ответа.
Сокращение повторяющихся ключей уменьшает объём формата, но выигрыш задержки не измерялся.

## Ошибки

- `400`: DTO не прошёл валидацию или `AI_DIALOGUE_CHECK_TEXT_REQUIRED`.
- `401`: нет авторизации.
- `403 USER_IS_NOT_OWNER`: чужой диалог.
- `404 AI_DIALOGUE_NOT_FOUND`: диалог отсутствует.
- `500 AI_DIALOGUE_CANNOT_PARSE_MESSAGE_CHECK`: некорректный/оборванный результат LLM.
- `504 LLM_TIMEOUT`: превышен таймаут ожидания.
- Другие ошибки провайдера/БД проходят через существующую обработку ошибок проекта.

## Файлы и проверки

Имена команды и моделей содержат `UserMessage`: проверяется только пользовательский черновик,
а не сообщения NPC. В `AiDialogue.dtoProps` входные поля описаны как
`checkUserMessageSpeechPart` / `checkUserMessageActionPart`, а свойства замечаний —
`checkUserMessageIssueTitle`, `checkUserMessageIssueSentence`,
`checkUserMessageIssueExplanation`, `checkUserMessageIssueExample`.

- `server/src/routes/aiDialogue/inputs/checkAiDialogueUserMessage.input.ts` — DTO.
- `server/src/models/aiDialogue/aiDialogueUserMessageCheck.out.model.ts` — внешний контракт.
- `server/src/features/aiDialogue/messageCheck/` — команда, промпт, парсер и тесты.
- `server/src/repo/aiDialogue/aiDialogueMessage.repository.ts` — чтение контекста.
- `server/src/db/dbConfig/dbConfig.ts`, `AiDialogue.dtoProps` — метаданные DTO; изменений схемы БД нет.
- `server/src/routes/aiDialogue/aiDialogue.controller.ts`, `openAPI.decorators.ts`, `aiDialogue.module.ts` — подключение маршрута.

```bash
cd server
npm test -- --testPathPatterns='messageCheck/|checkAiDialogueUserMessage.input|aiDialogue.controller|aiDialogueMessage.repository'
```

Проверяются доступ, обязательность одного поля, лимиты/типы DTO, серверные языки и контекст,
разделение ошибок по полям, Markdown, обрывы и некорректный протокол, ошибки провайдера/таймауты.
Тесты не вызывают платные модели и настоящую БД.

После запуска обновлённого сервера клиентские типы и функцию можно сгенерировать через
`cd face && npm run orval`; operationId — `AiDialogueController_checkAiDialogueMessage`.

Диктовка и WebSocket-маршрут реализуются отдельным этапом. Языки диктовки будут браться из диалога;
согласовано строгое ограничение распознавания изучаемым и родным языками, с удалением дубля при их совпадении.
