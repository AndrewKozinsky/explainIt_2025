# Мои диалоги

Секция «Мои диалоги» страницы `/dialogues` показывает три последних диалога текущего пользователя
и позволяет загрузить более ранние. Серверный контракт и клиентское отображение подключены.
Модель диалога, создание, сообщения и удаление описаны в [aiDialogue.md](aiDialogue.md).
Сценарии описаны в [aiDialogueScenario.md](aiDialogueScenario.md).

## Границы данных персонажей

Каждый элемент списка относится к одному AiDialogue. Его characters собирается только из связанных
AiDialogueCharacter и старых npcActions с тем же dialogue_id. Объединения персонажей на уровне сценария нет.
Слово «старые» относится к сообщениям до появления реестра AiDialogueCharacter внутри этого же диалога.
Одинаковый npcId в другом диалоге означает другого персонажа, с собственным именем и спрайтом.

## Серверный контракт

`GET /api/ai-dialogue?page=1&pageSize=3` возвращает только диалоги текущего пользователя.
Параметры необязательны: page=1, pageSize=3; принимаются целые числа, page≥1, 1≤pageSize≤100.
Сортировка — `created_at DESC, id DESC`, независимо от даты последнего сообщения или изменения настроек.
Ответ `AiDialoguesPageOutModel`:

```json
{
  "page": 1,
  "pageSize": 3,
  "total": 7,
  "totalPages": 3,
  "urlsExpireAt": "2026-10-24T15:00:00.000Z",
  "items": [
    {
      "id": 5,
      "scenario": {
        "id": 2,
        "title": "{\"ru\":\"Покупка абонемента в бассейн\",\"en\":\"Pool membership\"}"
      },
      "sourceLanguageCode": "en",
      "maxCefrLevel": null,
      "createdAt": "2026-10-20T10:00:00.000Z",
      "lastMessage": {
        "id": 90,
        "npcId": "anna",
        "name": "Anna",
        "role": "receptionist",
        "text": "Would you like a monthly membership?",
        "textType": "speech",
        "createdAt": "2026-10-23T15:30:00.000Z"
      },
      "sceneImage": null,
      "characters": [
        {
          "npcId": "anna",
          "name": "Anna",
          "role": "receptionist",
          "generationStatus": "generating",
          "emotionSheet": null
        }
      ]
    }
  ]
}
```

- `scenario` — вложенный объект с id и title; title остаётся JSON-строкой переводов.
- `maxCefrLevel: null` означает «без ограничения». Названия языка, подписи CEFR и относительных дат формирует клиент.
- `lastMessage` — именно последнее сохранённое `npcActions`. Более поздние userActions, userAvoidsNPC,
  help, worldEvent или sceneUpdate его не заменяют. Дата относится к этому же сообщению NPC;
  `updatedAt` контейнера не используется. При отсутствии npcActions — null.
- Внутри последнего npcActions непустые speech соединяются переносом строки в исходном порядке;
  если речи нет — аналогично action. Если нет ни речи, ни действий, text="", textType=null.
  Идентичность NPC берётся из payload и работает в старых сообщениях без character_id.
- `sceneImage` — готовое изображение **последнего sceneUpdate**. Если эта сцена ещё не имеет изображения,
  возвращается null, даже когда у более ранних сцен есть картинки. Генерация при чтении не запускается.
- `characters` содержит всех NPC за всю историю **конкретного диалога** (items[i].id), без пользователя
  и без ограничения количества. NPC других диалогов не включаются, даже если scenario.id и npcId совпадают.
  Идентификатор в этом списке — npcId, уникальный в рамках диалога. Старые NPC без записи AiDialogueCharacter
  восстанавливаются только для ответа из публичных метаданных сообщений, без записи в БД или генерации спрайтов.
  Их emotionSheet/generationStatus равны null. Новые NPC возвращаются и до готовности спрайта.
- `sceneImage` и `emotionSheet` используют AiDialogueImageOutModel: id/url/mimeType/width/height/layoutVersion.
  Для neutral используется верхняя левая ячейка emotion-grid-4x3-v1; обрезка и размеры — задача клиента.
- Ссылки R2 подписываются после owner-scoped чтения БД, действуют 6 часов;
  urlsExpireAt рекомендует обновить страницу данных через 5 часов. `Cache-Control: private, no-store`.
- Подсчёт, страница, NPC и выбранные сообщения читаются в RepeatableRead. MAX (id) по npcActions/sceneUpdate
  ограничивает загрузку двумя payload на диалог; полная история в приложение не передаётся.
  Старые NPC читаются одним параметризованным SQL-запросом для страницы с дедупликацией в БД.
- Для пустой страницы items=[], totalPages=Math.ceil (total/pageSize); при total=0 — totalPages=0.
  Кнопка следующей страницы нужна при page<totalPages. После создания/удаления клиент должен перечитать
  загруженную часть списка, чтобы смещение offset-пагинации не пропустило элементы.

Контракт списка заменяет прежний массив, отдельного маршрута совместимости нет.
Клиент использует этот контракт через Repository → Service → QueryFacade и сгенерированный Orval GET.
Удаление продолжает использовать существующий DELETE и клиентскую DeleteEntityModal.

Миграция `20261024120000_ai_dialogue_list_indexes` добавляет только составные индексы для списка и сообщений.
Схема и Prisma Client перегенерированы из dbConfig; миграцию нужно применить обычным `npm run migrate:deploy`
из server с нужным окружением. Пользователь подтвердил применение миграции и регенерацию Orval
перед реализацией клиентского списка.

Проверки этапа: серверные build, TypeScript и git diff --check проходят. Полный набор — 601 успешный тест,
14 ранее существовавших тестов пропущены; целевой набор диалогов — 369 успешных тестов.
Новые проверки покрывают параметры пагинации, owner-scoped запросы и согласованный снимок, ограниченную загрузку
сообщений, речь/действия последнего NPC, старые payload/NPC, отсутствие картинок и пустые страницы.
БД и R2 подменены; приложение, worker и платные генерации не запускались.

## Клиентский список

AiDialoguesPage монтирует UserAiDialoguesList только для авторизованного пользователя и передаёт userId.
Виджет сам загружает список через useUserAiDialogues/useInfiniteQuery. Серверные страницы имеют размер 10,
начальная страница — 1. Сначала видны только три карточки, остальные остаются в кэше. Каждое нажатие
«Предыдущие диалоги» добавляет до 10 карточек: 3 → 13 → 23. Если кэша недостаточно, загружается
следующая серверная страница. Постоянный pageSize исключает пропуски при offset-пагинации.
Ключ кэша — ['ai-dialogue', 'list', userId, { pageSize: 10 }], поэтому данные разных аккаунтов не смешиваются.
Сервис возвращает AiDialoguesPageModel; mapToAiDialoguesPage нормализует необязательные nullable поля Orval.

Карточки выводятся в порядке сервера. Только первая имеет крупную иллюстрацию 240×120, подпись
«Последний диалог», акцентные название и кнопку «Ответить». Остальные имеют иллюстрации 120×60.
Макет рассматривается как Retina 2×; адаптация под маленькие экраны не добавлялась.
LargeDialogueCard и MediumDialogueCard — отдельные обёртки; иллюстрация, описание, аватары, сообщение
и кнопки вынесены в общие компоненты ui/parts. Кнопки удаления и ответа используют Button;
href сохраняет ссылку, size="custom" оставляет размеры существующим стилям карточки.
Название берётся из scenario.title через pickLocalized, язык — через Intl.DisplayNames по локали интерфейса.
При maxCefrLevel=null выводится «Без ограничения».

Дата выводится из lastMessage.createdAt, по календарным дням в часовом поясе браузера:
сегодня/вчера/5 дней назад/месяц назад/2 года назад. При отсутствии сообщения дата не подменяется датой
создания диалога; вместо текста показывается «Пока нет сообщений персонажей».
Речь показывается обычным начертанием, действия — курсивом. Имя и роль находятся над текстом.
Для компактности текст ограничен двумя строками в первой карточке и четырьмя в остальных;
полный текст доступен в title и на странице диалога.

Универсальный CharacterAvatars принимает characters, size='small'|'medium' и необязательный maxVisible.
Без maxVisible показывает всех; превышение обозначается кругом +N. В карточке используются small/8
и medium/3 соответственно. Размеры — 26 и 32 CSS px. NPC учитывается и при отсутствии спрайта.
Каждый персонаж передаётся как { id, name, imageUrl }; метаданные API (layoutVersion, размеры)
в компонент не передаются. Отдельный CharacterFace показывает нейтральную ячейку: img размером 400%×300%
обрезается круглым контейнером, left/top=0. Отсутствие спрайта или ошибка загрузки показывают
заглушку с первой буквой имени. Иллюстрация без URL/при ошибке
сохраняет серый слот и размеры. Новый URL повторно разрешает показ изображения.

Кнопка «Предыдущие диалоги» видна, пока есть скрытые карточки в кэше или следующая серверная страница.
Ошибка догрузки сохраняет ранее загруженные карточки и возможность повторить запрос.
Начальная загрузка, ошибка с кнопкой повтора и пустой список обрабатываются отдельно.

Удаление открывает существующую DeleteEntityModal. После успешного DELETE незавершённые запросы списка
отменяются, все активные загруженные страницы последовательно перечитываются. Это предотвращает пропуск
диалога при смещении offset-пагинации. Новый первый элемент получает крупную карточку.
PATCH сложности обновляет только maxCefrLevel элемента в страницах кэша, сохраняя изображения,
участников и последнее сообщение; кэш detail обновляется отдельно.

Пока страница открыта, список сохраняет загруженные данные без автоматических запросов:
таймеры обновления подписанных URL, проверка готовности изображений, обновление при возвращении
фокуса и восстановлении соединения отключены. Поле urlsExpireAt не используется для обновления списка.
Догрузка по кнопке, повтор после ошибки и обновление после удаления остаются явными действиями.
Генерация из клиента не запускается.

## Проверки клиента

- `cd face && node --import tsx --test tests/aiDialogue*.test.ts` — 80 проверок диалогов, включая даты,
  реальный Service/API/Orval GET с подменой fetch, пагинацию и обновление сложности в постраничном кэше.
- `cd face && npx playwright test --config playwright.ai-dialogues.config.ts` — изолированный Vite-стенд
  с настоящими компонентами/стилями и подменённым API: размеры, нейтральная ячейка, догрузка/повтор,
  подтверждение/отмена удаления, отсутствие сообщений/изображений и пустой аккаунт.
- Для установленного Chromium вне стандартного пути можно задать PLAYWRIGHT_CHROMIUM_EXECUTABLE.
- ESLint изменённых файлов и git diff --check. Общий TypeScript остаётся ограничен шестью существующими
  ошибками типов языков в PhraseApi, TranslateApi и PhraseTranslationApi; новые файлы ошибок не добавляют.

Браузерный стенд не обращается к настоящей БД/R2 и не запускает генерацию; Next/i18n-ссылки заменены
локальным адаптером, сохраняющим префикс локали. На рабочей странице используются существующие Link и pageUrls.

- `server/src/repo/aiDialogue/aiDialogueList.queryRepository.ts` — пагинированный список с иллюстрацией,
