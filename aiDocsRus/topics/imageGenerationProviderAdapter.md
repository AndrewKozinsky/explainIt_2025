# Универсальный адаптер генерации изображений

Реализован в `server/src/infrastructure/imageGenerationProviderAdapter`. Поставщики: FLUX и OpenAI.
Адаптер не знает о диалогах, NPC, спрайтах, БД, R2, BullMQ или SSE. Текстовый `llmProviderAdapter` не расширяется.

## Общий контракт

`ImageGenerationAdapterService` выбирает поставщика по точному обязательному имени модели.
Нет дефолтной модели, подмены параметров, автоматических повторов внешних вызовов или fallback.

`ImageGenerationInput` содержит:

- `model`, `prompt`;
- необязательные упорядоченные `references`: исходные `Buffer`, `mimeType`, назначение `purpose`;
- `size`: `{ width, height }` либо `{ aspectRatio, resolution }`;
- необязательные `quality`, `format` (`png`/`jpeg`/`webp`), `abortSignal`.

Поставщик проверяет поддерживаемый набор до HTTP. `validateInput` вызывается потребителем до резервирования
платной отправки. `isConfigured(model)` проверяет наличие настройки без внешнего запроса, но не доступ к модели,
баланс или права аккаунта.

`generate(input)` возвращает `ImageGenerationResult`:

- `ready`: массив исходных изображений `{ bytes, contentType }`;
- `pending`: `operation` с `provider`, `model`, `version` и JSON-объектом `data`.

Потребитель сохраняет pending-реквизиты и передаёт их в `resume(operation, abortSignal)`. Это один внешний шаг,
без расписания или ожидания. Метод поставщика необязателен: отсутствие даёт `recovery_unsupported`, а не новую генерацию.
Контракт не требует polling URL или request ID у каждого поставщика. Смена настройки не переадресует операцию.
Реквизиты не содержат ключ API, сигнал отмены или байты. Временные URL нельзя публиковать или выводить в ошибки.
Потребитель проверяет MIME и геометрию перед публикацией.

## Ошибки и неопределённый исход

`ImageGenerationError`: безопасное сообщение, `code`, необязательный HTTP `statusCode` и `outcome`:

- `not_sent`: ошибка до отправки (валидация, отсутствующая настройка, заранее отменённый запрос);
- `unknown`: отправка началась, но надёжный результат не получен;
- `existing_operation`: ошибка продолжения известной операции.

Это описание отправки, а не политика повторов. При `unknown` нельзя автоматически отправлять новый платный запрос.
Тайм-аут/отмена после начала POST и неправильный ответ не доказывают отказ генерации или отсутствие списания.
Известную внешнюю операцию можно только продолжать с теми же реквизитами по политике потребителя.
Модерация/окончательный отказ имеют коды `moderated`/`operation_failed`.
Сырые ошибки Axios/SDK, секреты, промпты и байты в сообщения не попадают.

## OpenAI

`OpenAIImageGenerationProvider` использует существующий SDK и Images API. С референсами вызывается
`images.edit` (упорядоченные MIME-сохраняющие multipart-файлы), без референсов — `images.generate`.
Назначения добавляются в промпт как нейтральные инструкции `Image N: purpose`.
Отправляется `n: 1`; ответ base64 преобразуется в исходные байты, без ресайза/перекодирования.

Поддерживаемые модели: `gpt-image-2.5-sunburst`, `gpt-image-2.5-flare` и их фиксированные снимки
`gpt-image-2.5-sunburst-2026-09-08`, `gpt-image-2.5-flare-2026-09-08`.
Поддерживаемый адаптером набор: точные пиксели, quality `low`/`medium`/`high`, PNG/JPEG/WebP,
до 16 референсов. `xhigh`/`max`/`auto` пока явно отклоняются, хотя API допускает их: адаптер не заявляет
реализацию всех возможностей поставщика. Именованные FLUX-режимы площади не переводятся в пиксели автоматически.

Ограничения пикселей проверяются до HTTP: стороны кратны 16 и не больше 3840, отношение длинной стороны
к короткой не больше 3, площадь 655360..8294400. Промпт вместе с назначениями референсов не длиннее 32000 символов.
Байты референса и результата ограничены 32 MiB. Возвращённые size/quality/output_format, если API сообщает их,
должны совпасть с запросом; фактические размеры/формат проверяет потребитель.

Каждый вызов SDK получает `maxRetries: 0`, `timeout: 180000`, AbortSignal. Клиент также создаётся с нулём повторов.
Это важно: стандартные SDK-повторы могли бы повторить платный POST при потерянном ответе.
Нормализуются HTTP-статус и модерация, без содержимого ошибок SDK.

Images API возвращает готовый результат, а не BFL-style операцию. Реализация не предоставляет `resume`:
документированного восстановления потерянного ответа этим API нет. Request ID не используется как фиктивный
polling handle. Отключение автоматических повторов не даёт гарантии отсутствия повторной оплаты при ручной отправке.

Официальные источники:
[генерация и выбор API](https://developers.openai.com/api/docs/guides/image-generation),
[модели, параметры и геометрия](https://developers.openai.com/api/docs/guides/image-prompting),
[Images edits](https://developers.openai.com/api/reference/resources/images/methods/edit).

## FLUX

`FluxImageGenerationProvider` остаётся в универсальной infrastructure, но не используется feature диалогов.
Он оборачивает существующий `Flux3ImageAdapter`: HTTPS-проверки, региональный polling URL,
HTTP 503 со статусом задания, ограниченные download/тайм-ауты, AbortSignal в submit/poll/download.
`generate` возвращает BFL-операцию версии 1 с `{ requestId, pollingUrl }`;
`resume` делает один poll и скачивает оригинал при Ready. Временный sample URL не выдаётся вместо байтов.

Поддерживаются `flux-3-image`, `aspectRatio: 4:3 | 2:1`, `resolution: 768sq`, до 10 PNG/JPEG/WebP-референсов;
`grounding: false` задаёт поставщик. Точные пиксели, другие пресеты, quality и output format отклоняются.
Автоматического перенаправления FLUX в OpenAI нет.

## Регистрация и конфигурация

`ImageGenerationProviderModule` экспортирует фасад с обоими поставщиками и подключён в WorkerModule.
HTTP только сохраняет задания/outbox и не вызывает генерацию. Импорт модуля не запускает платные запросы.

Переменные проходят существующий `MainConfigService.getEnVariables()` → `get()`:
OpenAI использует `get().openAI.apiKey` (`OPENAI_API_KEY`), FLUX — `get().blackForestLabs.apiKey`.
Новых переменных и прямого чтения process.env в адаптере нет. SDK-клиент OpenAI создаётся лениво,
отдельно от текстового клиента, чтобы зафиксировать безопасные настройки повторов/тайм-аута.

## Диалоговый потребитель

Промпты, порядок референсов, спрайты и сохранение принадлежат `features/aiDialogue/imageGeneration`.
Feature использует OpenAI и не содержит BFL polling/восстановления: пользователь подтвердил отсутствие старых заданий.
Схема/применённые миграции не менялись; прежние внешние колонки остаются в БД, но новая feature их не заполняет.

`submitImageGenerationRequest.ts` заменяет `startOrResumeImageGenerationRequest.ts`: валидирует запрос,
атомарно резервирует отправку и результат в репозитории, затем вызывает общий фасад один раз.
Имя не обещает восстановления внешнего запроса, которого Images API не предоставляет.
Модель и параметры уже сохранены; claim добавляет только `resultS3Key` в существующий JSON input.
CAS по статусу и исходному input защищает от конкуренции и устаревшего снимка.

Worker восстанавливает только публикацию оригинала, уже находящегося по этому ключу в R2.
Откат/потерянное подтверждение коммита не удаляет файл активного задания. Если объекта нет после claim,
задание остаётся generating с безопасной ошибкой, очередь завершается UnrecoverableError для ручной проверки.
Нельзя просто сбросить статус в queued: это может создать повторную оплату.
Подробности и окна сбоев: [`aiDialogueImages.md`](aiDialogue/aiDialogueImages.md).

## Проверки

Изолированные тесты подменяют внешние SDK/HTTP, Prisma и R2: выбор модели, валидация до claim/HTTP,
референсы, AbortSignal, отсутствие fallback/повторов, готовый результат и отсутствие фиктивного восстановления,
неопределённые ответы, конкурентный claim и восстановление R2/БД. Отдельный настоящий Nest TestingModule
проверяет регистрацию двух поставщиков с подменённой конфигурацией без генерации.
Платные вызовы, реальные загрузки/удаления R2, миграции и коммит не выполнялись; клиент не менялся.

Результат: `npm run build`, `npx tsc --noEmit --incremental false`, `npm test`, `git diff --check` проходят.
262 теста в 32 наборах, 14 существующих тестов в 9 наборах пропущены.
Настоящий SDK с подменённым fetch подтвердил единственный POST при 503; настоящий Nest-контекст
с подменённым MainConfigService подтвердил регистрацию, без внешних запросов.
