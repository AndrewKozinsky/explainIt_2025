# Словарная статья

## Что делает функционал

Для слова, выражения или предложения создаёт статью на языке пользователя. Статья описывает слово в целом и не зависит
от текста, в котором его нажали: для одной фразы и языка сервер всегда отдаёт одну и ту же статью.

Основная часть содержит только необходимое и приходит сразу. Дополнительные разделы и иллюстрации генерируются в фоне и
видны при следующем открытии статьи.

## REST API

```
POST /universal-phrase-translation
```

```json
{ "universalPhraseId": 1, "targetLanguageCode": "ru" }
```

Вместо `universalPhraseId` можно передать `phraseText` и `sourceLanguageCode`. Ответ:

```json
{
  "id": 1,
  "universalPhraseId": 42,
  "targetLanguageCode": "ru",
  "translation": [
    {
      "type": "sense",
      "header": "принёс, привёз",
      "imageUrl": "https://...",
      "imageAspect": "landscape",
      "children": [
        { "type": "example", "sentence": "She brought a cake.", "translation": "Она принесла торт." }
      ]
    }
  ],
  "deepSections": [
    { "type": "block", "header": "Похожие слова", "children": [{ "type": "text", "text": "..." }] }
  ],
  "wordForms": [{ "forms": ["bring", "brought", "brought"] }],
  "status": "ready",
  "errorCode": null,
  "nonExistentWord": false,
  "createdAt": "2026-01-01T00:00:00.000Z",
  "transcription": null
}
```

Типы блоков: `block` (секция с заголовком), `sense` (одно значение), `example` (пример с переводом), `text` (Markdown),
`words` (похожие слова: `currentWord` и `similarWords` из `word` и `description`), `list` (`items` из `term` и `translation`).
В `example` предложение и перевод — Markdown: изучаемое слово и его перевод обёрнуты в `**`.
`deepSections` — `null`, пока фоновая задача не завершилась. При `nonExistentWord: true` поле `translation` равно `null`.
Плата с пользователя не взимается.

## Создание статьи

`GetOrCreateUniversalPhraseTranslationCommand` возвращает готовую статью из `UniversalPhraseTranslation`, а если её нет:

1. **Маршрутизатор** (DeepSeek Flash) определяет, существует ли текст, его тип и леммы. Типы: `lexical`, `inflected`,
   `functional`, `idiom`, `proper`, `free`, `sentence`, `other`. Промпт — `buildDictionaryRouterPrompt`. При сбое статья
   всё равно пишется, с типом `other`.
2. **Писатель** (`gpt-6.1-terra`) получает от маршрутизатора тип как подсказку и известные значения лемм. Структуру статьи
   он выбирает сам. Промпт — `buildUniversalPhraseTranslationPrompt`.
3. **Парсер** `parseUniversalPhraseTranslationResult` пропускает неизвестные и испорченные блоки. Ответ считается негодным,
   только если не осталось ни одного блока.
4. Значения привязываются к `WordSense`, статья и леммы сохраняются, в очередь ставятся фоновые задачи.

Модели и лимиты времени — в `dictionaryArticleConfig.ts`.

### Правила содержания

- Каждое предложение должно сообщать то, чего нельзя понять из перевода. Очевидные слова не определяются.
- Вступление пишется, только если одного перевода мало: другой объём значения, оттенок, ложный друг, нет эквивалента.
- Число значений не ограничено, но редкие исторические и узкоспециальные значения опускаются.
- У значения обычно два примера в разных ситуациях. Если у значения есть картинка, первый пример говорит о том же предмете
  или действии, но не пересказывает рисунок.
- Для идиом с образным выражением первым идёт дословный перевод.
- Статья написана на языке пользователя; на изучаемом языке только предложения примеров и цитаты слов.
- В заголовке значения через запятую идут только разные слова («водитель, шофёр»). Грамматические варианты одного слова не
  перечисляются: глагол даётся в одном виде («покупать»), обычно несовершенном, если значение не живёт в совершенном
  (`buy time` — «выиграть»). Искомая словоформа переводится в этой же форме (`wrote` — «написал»).
- У значений одной статьи заголовки не повторяются. Если слово языка пользователя переносит смысл так же, значения
  объединяются (`windows` дома и на экране — одно значение «окна»). Если перевод совпал случайно, в заголовок добавляется
  короткое уточнение в скобках: «драйвер (программа)» и «драйвер (клюшка для гольфа)».
- Транскрипция и формы слова в текст не включаются: для них есть отдельные блоки.

## Значения и иллюстрации

`WordSense` — одно значение леммы, общее для всех её форм и всех языков интерфейса. Писатель получает уже известные
значения и ссылается на них через `senseRef`, поэтому у форм одной леммы общая картинка.

Иллюстрация создаётся, только если сама называет значение. Картинка должна работать как карточка: без слова, перевода и
примера. На рисунке один элемент акцентного цвета, остальное серое. Правило для писателя: если показать готовый рисунок
десяти людям и спросить, что это за оранжевый элемент, одним словом, минимум девять должны назвать перевод значения или
близкий синоним. При сомнении картинки нет. Серое окружение допустимо, только если без него элемент не узнать.

Поэтому картинки получают `apple`, `bridge`, `jump`, `driver` (оранжевая фигура за рулём серого автобуса), но не `steady`
(скажут «лестница»), `uncanny` (скажут «кукла»), `client`, `bring`, `give up`. Большинство прилагательных, наречий,
абстрактных слов и идиом остаётся без иллюстрации. Рисунок придумывается от значения, а не от примера.

Писатель выбирает вид картинки (`scene`, `contrast`, `comic`). Формат следует из вида:

| Формат | Вид | Размер генерации |
|---|---|---|
| `landscape` | `scene`, `contrast` | 1024×640 |
| `strip` | `comic` | 1536×512 |

Каждый запрос получает общий стиль серии и образец своего вида картинки из
`features/universalPhraseTranslation/enrichment/styleSamples`, поэтому иллюстрации складываются в серию.

Модель — `gpt-image-2` с качеством `low`. Результат пережимается в WebP шириной до 800 px и лежит в R2 по ключу
`dictionary-images/word-senses/<id>.webp`.

## Фоновая догенерация

Очередь `dictionary-enrichment`, обработчик `DictionaryEnrichmentProcessor` в worker. Задачи ставятся сразу после сохранения
статьи; сбой постановки не влияет на её выдачу.

- **Глубокие разделы** (`GenerateDictionaryDeepSections`): похожие слова, типичные ошибки, полезные сочетания, происхождение
  идиом. Не создаются для типов `proper`, `free`, `sentence`. Три попытки.
- **Иллюстрация значения** (`GenerateWordSenseImage`): одна попытка, потому что потерянный ответ платной генерации нельзя
  отправлять повторно. Статус переводится из `pending` в `generating` атомарно, поэтому одно значение не оплачивается дважды.

Клиент не ждёт эти задачи и не обновляет открытую статью.

## Формы слов

`getWordForms` подставляет заранее подготовленные формы при каждой выдаче статьи, модель их не генерирует. Поиск идёт по
леммам от маршрутизатора. Если леммы нет в справочнике, блока форм нет. Сейчас справочник есть для английского
(`wordForms/englishWordForms.ts`): неправильные глаголы, множественное число, степени сравнения.

## Нормализация текста

Текст фразы приводится к стандартной форме функцией `normalizePhraseString` (`server/src/utils/stringUtils.ts`):

- пробелы по краям обрезаются, повторяющиеся пробелы заменяются одним;
- типографские апострофы и кавычки заменяются на обычные;
- знаки препинания по краям убираются, апострофы по краям и знаки внутри фразы сохраняются;
- текст переводится в нижний регистр.

Поэтому «Pretty much.», «pretty much» и «“Pretty much!”» — одна фраза с одной статьёй. Клиент фразу не нормализует.

## База данных

`UniversalPhraseTranslation`: `universal_phrase_id`, `target_language_code` (уникальная пара), `translation` (JSON блоков),
`deep_sections` (JSON блоков), `lemmas` (JSON массива), `status`, `error_code`, `non_existent_word`, `created_at`.

`WordSense`: `source_language_code`, `lemma`, `gloss` (уникальная тройка), `visual_kind`, `visual_aspect`, `visual_prompt`,
`image_s3_key`, `image_status` (`none`, `pending`, `generating`, `ready`, `failed`).

## Клиент

- `face/widgets/dictionary/ui/PhraseTranslationResult/` — блок форм, блоки статьи и глубокие разделы. В блоке значения
  пояснения стоят над картинкой, первый пример сразу под ней. Значения нумеруются, если их больше одного. Между соседними
  примерами разделитель ставится стилями. Жирные слова в примерах окрашиваются через `className` компонента `StyledMarkdown`.
  Нажатие на карточку похожего слова открывает статью о нём.
- `face/entities/universalPhrase/repository/` — модели и маппинг ответа.
- `face/entities/universalPhrase/UniversalPhraseService.ts` — запрос и кэш в памяти на время жизни страницы.
- `face/widgets/dictionary/lib/fetchDictionaryArticle.ts` — загрузка статьи в стор виджета.

## Ключевые файлы сервера

- `features/universalPhraseTranslation/GetOrCreateUniversalPhraseTranslation.command.ts` — создание статьи.
- `features/universalPhraseTranslation/enrichment/` — фоновые задачи и образцы стиля.
- `features/universalPhraseTranslation/wordForms/` — справочник форм.
- `repo/universalPhrase/universalPhraseTranslation.queryRepository.ts` — ответ клиенту, ссылки на картинки и формы.
- `repo/universalPhrase/wordSense.repository.ts` — значения.
- `infrastructure/queues/dictionaryEnrichment.queue.ts` — постановка фоновых задач.
