# Озвучка диалогов с ИИ

## Назначение

Озвучиваются описание сцены (`sceneUpdate.content`) и каждая реплика NPC (`speech` в `npcActions`) на изучаемом
языке. Переводы, невербальные действия, пользовательские сообщения, `help`, `worldEvent` и технические метаданные
не озвучиваются. Списание с баланса пользователя не производится.

Озвучку запрашивает клиент, и только для сохранённых сообщений. Генерация текста хода озвучку не запускает.
Каждая реплика синтезируется не больше одного раза: файл хранится в R2 и отдаётся повторно.

На странице две настройки, обе хранятся в LocalStorage и по умолчанию включены:

- **«Автоозвучка»** — клиент сам запрашивает и проигрывает озвучку нового ответа, как только он сохранён.
  Если выключена, озвучка запрашивается только нажатием кнопки воспроизведения.
- **«Текст реплик»** — показывать текст новых реплик и описаний сцен. Скрытый текст открывается вручную.

## Голос NPC и диктора

Текстовый промпт просит для нового NPC добавить до первой action/speech:

```text
npcActions|officer_1|Alex|border officer|neutral
appearance:
an adult officer with short grey hair
voice:
{"voice":"ash","instructions":"An adult male voice with a low timbre, steady official delivery, restrained intonation and a natural English accent."}
speech:
Your passport, please.
Ваш паспорт, пожалуйста.
```

JSON `voice` — скрытые метаданные без перевода: он не становится сообщением, действием или картой слов.
Допустимые базовые голоса берутся из `OPENAI_TTS_VOICES`; instructions — непустая строка до 3000 символов.
Модель иногда пишет поле в одну строку (`voice: {...}`); обе формы читает `readNpcMetadataField`.
Голос учитывается только до первой метки `action:`/`speech:`, чтобы текст реплики не принять за поле.

`parseAiDialogueEvents` возвращает корректные профили в `npcVoices`. Транзакция сохранения хода
(`AiDialogueTurnRepository.saveGeneratedTurn`) записывает их в `AiDialogueVoice` через `createMany` со `skipDuplicates`.
Таблица уникальна по `(dialogue_id, npc_id)`, поэтому первый профиль NPC не меняется при его возвращении,
компакции или повторном описании. Профиль сохраняется, даже если NPC в этом ходе только действует и не говорит.
Некорректный профиль игнорируется.

Если у NPC нет сохранённого профиля, его реплики не озвучиваются: запрос возвращает
`AI_DIALOGUE_AUDIO_NOT_AVAILABLE`. Чужой или базовый голос молча не подставляется.

`audio/aiDialogueAudioConfig.ts` задаёт:

- модель `gpt-4o-mini-tts-2025-12-15`;
- формат MP3, MIME `audio/mpeg`, speed=1, timeout=60 секунд;
- единый голос диктора `cedar` для описаний сцен: спокойное естественное повествование и чёткая артикуляция.

Профиль NPC постоянный; эмоция сообщения не добавляет изменяющихся инструкций. Инструкции повышают стабильность
манеры, но не гарантируют идентичное звучание каждого синтеза.
Контракт поставщика: [OpenAI TTS](https://developers.openai.com/api/docs/guides/text-to-speech).

## REST

`POST /api/ai-dialogue/:id/audio` — только владельцу, `Cache-Control: private, no-store`.

```json
{ "messageId": 433, "actionIndex": 1 }
```

`actionIndex` — индекс реплики в `actions` сообщения NPC или `-1` для описания сцены.
Ответ: `{ "url": "<подписанная ссылка R2>", "mimeType": "audio/mpeg" }`. Ссылка подписывается по окнам
(см. «Ссылки на файлы R2» в `server.md`). Текст, голос и ключ хранилища клиенту не отдаются.

Ошибки:

- 404 `AI_DIALOGUE_NOT_FOUND` — сообщения нет в этом диалоге;
- 403 — диалог принадлежит другому пользователю;
- 400 `AI_DIALOGUE_AUDIO_NOT_AVAILABLE` — в позиции нет озвучиваемого текста (невербальное действие,
  несуществующий индекс, `-1` не у сцены) или у NPC нет голоса;
- 500 `AI_DIALOGUE_AUDIO_GENERATION_FAILED` — синтез или загрузка в R2 не удались.

Доступ проверяется до синтеза. Текст берётся из сохранённого сообщения, а не из запроса.

## Генерация по запросу

`GenerateAiDialogueAudio.command.ts`:

1. Находит сообщение, проверяет диалог и владельца, выбирает текст и голос (диктор или профиль NPC).
2. `AiDialogueAudioRepository.startGenerationIfNeeded` пытается начать генерацию:
   - записи нет — создаёт её со статусом `generating`, и этот запрос синтезирует файл;
   - прошлая генерация завершилась `failed` или зависла (`generating` без обновления дольше 2 минут) —
     этот запрос перезапускает её;
   - файл готов (`ready`) — сразу возвращает ссылку;
   - генерация идёт в параллельном запросе (двойной клик, вторая вкладка) — ждёт её результата до 90 секунд,
     проверяя запись каждые 500 мс, и не запускает второй синтез.
3. Синтезирует MP3 через `TtsAdapterService` (OpenAI, существующий `OPENAI_API_KEY`), проверяет ответ
   `isValidDialogueMp3`, загружает в R2 и ставит `ready`.
4. При ошибке ставит `failed` и возвращает 500. Следующий запрос пробует снова.

`isValidDialogueMp3` ограничивает размер 32 MiB, разбирает размер ID3 и требует хотя бы один целый
кадр MPEG Layer III. Это структурная проверка, а не декодирование файла или оценка качества.

HTTP-запрос ждёт синтеза (обычно 1–5 секунд). Очереди, worker'а и SSE-уведомлений у озвучки нет.

## БД и R2

Таблица `AiDialogueAudio`: `message_id` (каскадное удаление вместе с сообщением), `action_index`, `s3_key`,
`status` (`generating`, `ready`, `failed`), `created_at`, `updated_at`. Уникальность — `(message_id, action_index)`.
`updated_at` в схеме не обновляется автоматически: репозиторий выставляет его при смене статуса,
по нему определяется зависшая генерация.

Ключ файла: `ai-dialogue-audio/generated/<region>/<mode>/<dialogueId>/<uuid>.mp3`. При перезапуске генерации
используется ключ из записи. DELETE диалога собирает ключи озвучки вместе с изображениями в owner-scoped транзакции,
каскадно удаляет записи и после коммита удаляет файлы из R2 (`CleanupAiDialogueAudio.deleteFiles`).
Сбой удаления файла не отменяет успешный DELETE; фоновой очистки R2 у озвучки нет.

## Клиент

### Проигрыватель

`DialogueAudioPlayer` владеет единственным `HTMLAudioElement` страницы. Его состояние расположено вне компонентов
сообщений и доступно через `useSyncExternalStore` и `DialogueAudioProvider`.
Озвучка адресуется `{ messageId, actionIndex }`, ключ — `getDialogueAudioKey`. Файл запрашивается через
Repository → Service (`aiDialogueService.getAudio`) → Orval.

- Одна озвучка — один запрос: повторные вызовы ждут уже начатый запрос или сразу получают полученный файл.
  После ошибки запроса следующий вызов снова обращается к серверу.
- Ручное нажатие запрашивает файл и играет его, как только сервер ответит. Если пользователь за это время
  выбрал другую реплику, поздний ответ не запускается.
- Нажатие на играющую или загружаемую реплику останавливает её с сохранением позиции; следующее нажатие продолжает.
  Выбор другой реплики сбрасывает позицию предыдущей.
- Ручное нажатие снимает оставшуюся автоозвучку текущего ответа. Следующий ответ снова озвучивается автоматически.
- Если воспроизведение не началось за 15 секунд или медиа сообщило об ошибке (например, истекла ссылка),
  показывается ошибка, а следующее нажатие запрашивает ссылку заново.
- Запрет autoplay браузером (`NotAllowedError`) не считается ошибкой: в настройках появляется «Включить звук»,
  после нажатия выбранная озвучка продолжается.

### Автоозвучка

`openAiDialogueStream` передаёт в `useAiDialogueAudio` каждое новое сохранённое сообщение текущего хода
(SSE-событие `message` во время генерации). Replay истории при подключении не озвучивается.
`getVoicedAudioAddresses` выбирает описание сцены и реплики с текстом (без невербальных действий).

- Значение «Автоозвучки» берётся в момент сохранения ответа. Выключенная автоозвучка не запрашивает файлы;
  её выключение не останавливает уже начатую озвучку.
- Файлы всех текстов ответа запрашиваются сразу, а играют по порядку текста, не по готовности.
  Текст, файл которого не удалось получить, пропускается.
- Первый озвучиваемый текст нового ответа снимает очередь предыдущего и останавливает его текущий файл.
  `turnStarted` сам по себе предыдущую озвучку не прерывает.
- Разрыв SSE снимает автоозвучку и останавливает звук; полученные файлы остаются для ручного запуска.

### Кнопка воспроизведения

Кнопка есть только у сохранённых сообщений: у превью ещё нет `messageId`. Если текст виден, кнопка стоит
в начале его первой строки; если скрыт — рядом с кнопкой скрытого текста. Во время запроса или загрузки
показывается индикатор, при ошибке — предупреждение («Не удалось озвучить. Повторить»).

## Ключевые файлы

Сервер:

- `features/aiDialogue/audio/GenerateAiDialogueAudio.command.ts` — проверка доступа, синтез, R2;
- `features/aiDialogue/audio/isValidDialogueMp3.ts` — структурная проверка MP3;
- `features/aiDialogue/audio/CleanupAiDialogueAudio.service.ts` — удаление файлов удалённого диалога;
- `repo/aiDialogue/aiDialogueAudio.repository.ts` — сообщение, голос, запись озвучки и её статус;
- `repo/aiDialogue/aiDialogueTurn.repository.ts` — сохранение голосов NPC вместе с ходом;
- `routes/aiDialogue/inputs/generateAiDialogueAudio.input.ts`, `models/aiDialogue/aiDialogueAudio.out.model.ts` — контракт.

Клиент:

- `entities/aiDialogue/audio/DialogueAudioPlayer.ts` — проигрыватель и автоозвучка;
- `entities/aiDialogue/audio/getVoicedAudioAddresses.ts`, `dialogueAudioTypes.ts` — адреса озвучки;
- `_pages/aiDialogue/AiDialoguePage/fn/useAiDialogueAudio.ts` — подключение к странице и SSE;
- `widgets/aiDialogueMessages/ui/audio/*` — кнопка воспроизведения.

Серверные тесты (`npm test` из server) подменяют OpenAI, R2 и БД: качество голосов они не проверяют.
Клиентские — `npm run test:ai-dialogue` из face.
