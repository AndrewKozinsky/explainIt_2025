# Форма ответа пользователя в диалоге

`face/widgets/aiDialogueForm/AiDialogueForm/AiDialogueInput.tsx` показывает вкладки «Реплика» и «Действие»,
кнопку «Уйти от разговора», редактор и кнопки диктовки и отправки. Черновики вкладок независимы.
Для отправки достаточно заполнить хотя бы одну часть.

## Интерфейс

- Одно `textarea` показывает активную часть. При переключении сохраняются текст и положение курсора
  обеих вкладок. Высота поля обновляется по `scrollHeight`.
- Placeholder реплики — `Hi, how’s it going?`, действия — `I opened the door`.
- Ошибка отправки или диктовки отображается под полем.
- Внизу находятся статус, кнопка диктовки и «Отправить». На узком экране статус занимает отдельную строку.

| Состояние | Статус |
|---|---|
| Пустая активная часть | Напечатайте или продиктуйте реплику или действие |
| Подключение микрофона | Подключаю микрофон… |
| Запись после ready | Слушаю… |
| Остановка до окончательного результата | Завершаю распознавание… |
| Запрос отправки | Отправляю ответ… |

Тексты переведены на 7 языков интерфейса и хранятся в `messages/{locale}/aiDialogueForm.json`.
`draftStatus` возвращает ключ статуса, `DraftErrorKey` — ключ ошибки диктовки.

## Кнопка отправки

«Отправить» доступна при заполненной реплике или действии. Enter отправляет ответ, Shift+Enter вставляет
перенос строки. Enter во время ввода через IME оставляет управление редактору ввода. Во время диктовки,
запроса отправки и генерации ответа NPC отправка заблокирована.

Форма отправляет один `POST .../messages` с репликой и действием в этом порядке. Пробелы по краям
удаляются, пустые части пропускаются. Лимит на клиенте составляет 4000 UTF-16 единиц для каждой части.
На время запроса редактор, вкладки, диктовка и кнопки формы заблокированы.

При ошибке оба черновика остаются в форме. Повтор использует тот же `requestId`, пока отправляемый
текст совпадает. После правки текста создаётся новый ключ. При подтверждении отправки форма очищается,
итоговый текст появляется в ленте. Кнопка с числом замечаний открывает [разбор сообщения](aiDialoguePage.md#панель-сообщение).

«Уйти от разговора» отменяет текущую диктовку и отправляет отдельное событие `userAvoidsNPC`.
После подтверждения ухода черновики очищаются.

`fn/AiDialogueDraftController.ts` управляет черновиком независимо от React.
`useAiDialogueDraft` подключает контроллер через `useSyncExternalStore` и передаёт ему транспорт
микрофона и отправки. Пока баланс исчерпан, вместо формы показывается уведомление. Форма возвращается
после начисления с черновиками текущего диалога.

## Данные для разбора ответа пользователя

В ответе `POST .../messages` и в сообщении из истории SSE используется одна модель. У события
`userActions` обязателен массив `payload.textReview`. Его элементы соответствуют элементам `payload.actions`
с теми же индексами. `payload.actions[].content` — итоговый текст, который показывается в диалоге
и передаётся в контекст персонажа. Если итоговый текст отличается от `originalText`, это исправленный
вариант той же части. Реплика и действие могут иметь разные результаты анализа.

Пример формата с заполненным разбором:

```json
{
  "id": 17,
  "dialogueId": 3,
  "payload": {
    "type": "userActions",
    "actions": [
      {
        "type": "speech",
        "content": "She goes home."
      },
      {
        "type": "action",
        "content": "I nod."
      }
    ],
    "textReview": [
      {
        "originalText": "She go home.",
        "analysis": {
          "critical": [
            {
              "title": "Согласование",
              "sentenceMarkdown": "She **go** home.",
              "explanationMarkdown": "После **she** нужна форма **goes**."
            }
          ],
          "suggestions": []
        }
      },
      {
        "originalText": "I nod.",
        "analysis": {
          "critical": [],
          "suggestions": []
        }
      }
    ]
  },
  "createdAt": "2026-11-17T10:00:00.000Z"
}
```

Сервер проверяет от одной до восьми частей за запрос. Текст каждой части ограничен 4000 символами.
Он исправляет однозначные ошибки в грамматике, орфографии, пунктуации и словоупотреблении.
Иноязычные слова, фразы и целые реплики или действия переводятся на изучаемый язык. Разбор объясняет
замену на языке подсказок. Если при изучении языка с латиницей в итоговом тексте осталась кириллица
вне дословной цитаты из оригинала, сервер повторяет анализ один раз. При повторном сбое сообщение
остаётся черновиком.
Предложения по стилю и пояснения к неоднозначным фразам сохраняются в `suggestions`.
Два пустых массива в `analysis` означают, что анализ выполнен и замечаний нет. `textReview` хранится
вместе с событием в JSON строки `AiDialogueMessage`. У `userAvoidsNPC` и событий персонажей поля разбора нет.

[Серверный контракт отправки](aiDialogue.md#отправка-сообщения-действие-пользователя).

## Диктовка и выделение

`entities/aiDialogue/dictation/openAiDialogueDictation.ts` открывает браузерную запись и
`WS(S) /api/ai-dialogue/:id/dictation` на текущем origin. Авторизационная cookie передаётся браузером.
MediaRecorder выбирает WebM/Opus или Ogg/Opus; запись начинается
после серверного ready и выдаёт фрагменты каждые 200 мс. Если эти контейнеры недоступны,
используется AudioContext/AudioWorklet: моно PCM16LE с частотой контекста (48 кГц).
MP4 не передаётся в потоковый API: он указан у Soniox только для файловой транскрибации.
Форматы: [Soniox real-time transcription](https://soniox.com/docs/stt/rt/real-time-transcription#audio-formats).
Worklet выдаёт порции по 2048 сэмплов и сбрасывает короткий хвост перед подтверждением stop.
Граф не проигрывает записываемый голос в динамиках; AudioContext закрывается при завершении или отмене.
Серверные правила: [`aiDialogueDictation.md`](aiDialogueDictation.md).

Перед записью фиксируются исходный текст и selectionStart/selectionEnd. Для pointer-нажатия
«Диктовать» предотвращается переход фокуса на кнопку; при клавиатурном запуске используется
сохранённое выделение. Во время распознавания textarea остаётся readOnly и показывает
выделенный вставляемый фрагмент. Префикс и суффикс исходного текста не меняются,
выделенные слова заменяются диктовкой; дополнительные пробелы автоматически не добавляются.
Пустая диктовка не удаляет исходное выделение.

partial заменяет предварительный хвост; final добавляется к подтверждённой части без новых пробелов.
done заменяет вставку полным финальным текстом один раз. Переключение вкладок и отправка во время
диктовки запрещены, чтобы запись не попала в другое поле.

«Завершить» останавливает recorder. Микрофон освобождается при событии stop, а серверный stop
отправляется после последнего dataavailable и всех последовательных Blob → ArrayBuffer преобразований.
До done поле серое, отправка и повторная диктовка заблокированы.
При нажатии «Завершить» до подключения микрофона текущая попытка отменяется.

При сетевом сбое сохраняется подтверждённая часть и отбрасывается предварительный хвост;
если подтверждённого текста не было, восстанавливается исходный текст с выделенными словами.
Превышение 4000 символов останавливает запись без обрезания окружающего текста.
Ошибки доступа к микрофону, отсутствия устройства и соединения отображаются в форме.
Автоматического переподключения и повтора аудио нет.

Клиент ограничивает очередь аудио 1 МиБ / 64 фрагментами, WebSocket-буфер 512 КиБ;
большие Blob отправляются частями по 64 КиБ. Таймаут подключения — 30 с, записи — 5 мин,
ожидания завершения — 60 с. Сервер применяет собственные ограничения.

При смене dialogueId/размонтировании отменяются recorder, дорожки микрофона и WebSocket,
очищаются таймеры; позднее разрешение getUserMedia также освобождает полученные дорожки.
Возвраты старых операций игнорируются. `useAiDialogueSendMessage` не добавляет запоздалый POST-ответ
прежней страницы в общий стор после навигации.

## Основные файлы и тесты

- `face/widgets/aiDialogueForm/AiDialogueForm/AiDialogueInput.tsx` — редактор и смена экземпляра формы по dialogueId.
- `AiDialogueDraftControls.tsx`, `AiDialogueDraftFeedback.tsx` рядом — кнопки, статусы и ошибки.
- `fn/AiDialogueDraftController.ts`, `fn/aiDialogueDraftState.ts` — состояние черновика, ключи повтора и правила отправки.
- `fn/useDraftTextarea.ts` — автовысота и видимое выделение диктовки.
- `face/entities/aiDialogue/messageCheck/userMessageCheckTypes.ts` — типы независимые от Orval.
- `face/entities/aiDialogue/dictation/openAiDialogueDictation.ts` — браузерный транспорт записи.
- `createDictationRecorder.ts` рядом и `face/public/audio/ai-dialogue-pcm-worklet.js` — выбор формата и PCM fallback.
- `face/tests/aiDialogueDraft.test.ts`, `aiDialogueDictation.test.ts` — изолированные тесты.
- `face/e2e/aiDialogueForm.spec.ts` — форма в настоящем браузере с подменой API/SSE/микрофона/WebSocket.

```bash
cd face
npm run test:ai-dialogue
npx playwright test e2e/aiDialogueForm.spec.ts --project=chromium --workers=1
```

Для Playwright нужен установленный браузер соответствующей версии. Тесты подменяют LLM, Soniox, микрофон и БД.
