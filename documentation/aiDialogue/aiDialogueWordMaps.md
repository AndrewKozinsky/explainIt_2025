# Карта выбора словарной фразы в диалогах

Карта «слово → группа слов для словаря» генерируется в конце того же ответа LLM, что и сюжетные сообщения.
Сначала модель выдаёт обычный построчный текст и переводы: пользователь видит их через SSE chunk.
После всех сюжетных блоков модель дописывает технический раздел wordMaps:.
Сервер разбирает его и сохраняет карты вместе с сообщениями; SSE message и replay уже содержат payload.wordMap.
Подтверждение хода и turnDone происходят после завершения всего потока, включая карту.

Словарь получает только строку слова/выражения, без контекста, переводов или объяснений.
Перевод всего блока остаётся прежним.

## Группы слов

Группа — минимальный набор исходных слов, которые нужно искать в словаре вместе, потому что пословный перевод
даёт неверный или бессмысленный результат. Группа сама несёт минимальный контекст, поэтому Словарю не нужно
знать предложение. Клик по любому слову группы отправляет в Словарь всю группу. Слово вне групп отправляется одно
и в карте не упоминается.

В группы объединяются:

- фразовые глаголы и глаголы с отделяемой приставкой: `went back`, `put … away`, `rufe … an`;
- глаголы с предлогом, меняющим значение, возвратные и составные глаголы: `me acuerdo de`, `yardım edebilirim`;
- составные существительные и сочетания, значение которых не равно сумме слов: `security camera`;
- идиомы, устойчивые и парные конструкции: `either … or`, `ne sais pas`, `Il y a`, `You belong in jail`;
- вспомогательные конструкции: `Do you have`, `I don’t have`, `to declare`;
- предлог или частица вместе со словами, которые определяют его значение в этом предложении: `down my trousers`.

Не объединяются слова, сохраняющие обычное значение: артикль или прилагательное с существительным, подлежащее
с обычным глаголом, глагол с обычным дополнением. В сомнительном случае модель объединяет: лишняя группа стоит
ученику одного дополнительного действия, пропущенная — неверного понимания.

Ограничения группы:

- не меньше двух слов, в исходном порядке, в исходных формах; карта не заменяет их словарной формой и не содержит
  перевода или объяснения;
- промежуточные слова, не входящие в выражение, пропускаются: в
  `She put the beautifully wrapped birthday present that she had bought for her sister the day before away in the closet.`
  группа — только `put away`;
- группа остаётся внутри одного простого предложения и как можно короче;
- одно слово входит не больше чем в одну группу.

Правила действуют для всех изучаемых языков (`source_language_code` диалога). Для каждого языка модель учитывает
его собственные выражения и конструкции; английские схемы нельзя механически переносить на другие языки.
Семантический выбор зависит от модели; примеры в промпте задают ожидаемое поведение.

## Клики

Клиент для клика и подсветки при наведении берёт запись нажатого слова: у всех слов группы она одинаковая.
Клик сразу отправляет готовую phrase из карты или само нажатое слово, если записи нет.
Во время стрима, при отсутствии/ошибке карты и в старых сообщениях действует тот же запасной путь.
Позднее появление карты не подменяет предыдущий словарный запрос. Нет ожидания анализа,
надписей о разборе и предложения открыть диалог повторно.
Сообщения пользователя всегда передают только нажатое слово.

## Контракт ответа LLM

После всех обычных блоков и пустой строки:

```text
wordMaps:
{"content":"Do you have anything to declare?","groups":[["Do","you","have"],["to","declare"]]}
{"content":"Look at her, then look at me and get up.","groups":[["look",["at",1]],["get","up"]]}
```

Один компактный JSON объект на строку для каждого предложения каждой исходной content строки: строка из трёх
предложений даёт три объекта. content дословно повторяет предложение. Пустые groups допустимы.
Слово записывается строкой. Если слово с таким написанием встречается в предложении несколько раз и нужно не первое
вхождение, оно записывается как `["слово", n]`, где n — номер вхождения среди слов с точно таким же написанием
в этом предложении, начиная с нуля. Строка без номера означает первое вхождение.
Модель не вычисляет символьные offsets и IDs. Переводы, внешность, визуальные описания и заголовки не анализируются.

Пример полного ответа в промпте заканчивается разделом wordMaps:, а запрос хода напоминает о нём последней строкой:
в истории события показаны без карты, и без напоминания модель заметно чаще пропускает раздел.

`splitWordMapFooter` отделяет метаданные до сюжетного парсинга. Клиентское превью также исключает этот раздел.
`attachInlineWordMaps` токенизирует исходный текст через Intl.Segmenter с языком диалога.
Запись карты сопоставляется с блоком по тексту: она применяется к каждому месту блока, где встречается её content, —
ко всей строке или к одному её предложению. Номера вхождений считаются внутри этого фрагмента. Совпадение,
разрезающее слово, пропускается. Сервер проверяет ссылки на слова и их порядок. Группа с ошибкой или со словом,
уже вошедшим в предыдущую группу, пропускается целиком. Некорректные группы/строки пропускаются независимо;
ошибка или отсутствие карты не вызывает повторную генерацию или turnError. Граница простого предложения
и краткость группы — правила промпта, сервер их не проверяет.
Для каждого слова группы сервер сохраняет отдельную запись selections с одинаковыми wordIds и phrase.

Для sceneUpdate/help/worldEvent ключ блока `content`; для каждого действия/реплики NPC — `action:<index>`.
Все эти типы получают карту. userActions/userAvoidsNPC исключены.

```ts
{
    status: 'ready',
        blocks
:
    {
        content: {
            content: 'Do you have anything to declare?',
                words
        :
            [{id: 0, text: 'Do', start: 0, end: 2}, /* ... */],
                selections
        :
            [{wordId: 0, wordIds: [0, 1, 2], phrase: 'Do you have'}, /* ... */]
        }
    }
}
```

start/end — UTF-16 offsets в оригинале, end исключительный. phrase строится сервером:
соседние слова сохраняют исходную пунктуацию между ними, несоседние группы соединяются пробелом.
Клиент использует серверные позиции, если content совпадает; иначе сегментирует текст самостоятельно.
Карта хранится в JSON payload сообщения; отдельных REST DTO и SSE-событий для неё нет.
В старых payload могут встречаться статусы pending/failed и поле wordMapRequestId: такие карты не блокируют словарь,
а wordMapRequestId скрывается при чтении.
