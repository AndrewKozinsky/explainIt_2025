# Страница диалога с ИИ (AiDialoguePage)

## Что делает функционал

Страница `/dialogues/{dialogId}` (`_pages/aiDialogue/AiDialoguePage`), на которой пользователь общается с LLM-«NPC» в
рамках выбранного сценария. Это **клиентская** часть фичи AiDialogue — серверная часть (доменная модель, REST,
SSE-протокол, генерация хода, компакция) описана в
`documentation/aiDialogue/aiDialogue.md`.

Страница полностью клиентская (`'use client'`). Взаимодействие:

- диалог загружается по REST (`GET /ai-dialogue/:id`) через TanStack Query;
- обмен сообщениями — через постоянный SSE-поток (`EventSource`), открытый хуком `useAiDialogueStream`;
- пользователь отправляет действие/реплику и «завершает» диалог через REST (`POST /ai-dialogue/:id/messages`);
- клик по слову в сохранённом сообщении показывает перевод блока, выбирает связанные слова по серверной карте и передаёт
  фразу в правую панель. Подробности: `aiDialogueWordMaps.md`.

Языки: `dialogue.sourceLanguageCode` — изучаемый язык (реплики NPC), `dialogue.targetLanguageCode` — родной язык (поле
`translation`). Словарь в правой панели строится по `sourceLanguageCode`.

## Выбор сложности текста

`AiDialogueModel.cefrLevel: 'A1' | 'A2' | 'B1' | 'B2' | 'C1' | null` содержит сохранённую сервером границу сложности.
`entities/aiDialogue/ui/TextLevelSwitcher.tsx` в панели `AiDialogueSettings` показывает A1/A2/B1/B2/C1/Any; `Any`
соответствует `null`.
При загрузке и возвращении к диалогу выбранный уровень берётся из REST-модели, без локального значения A1 по умолчанию.

Нажатие вызывает `AiDialogueService.updateDialogue(id, input)` через хук `useAiDialogueTextLevel`.
Цепочка: Repository → AiDialogueApi → сгенерированный `aiDialogueControllerUpdateAiDialogue` →
`PATCH /api/ai-dialogue/:id`. В теле передаётся `{"cefrLevel":"A2"}` или `{"cefrLevel":null}`.
Поле необязательно: отсутствие оставляет прежнее значение. Компоненты не вызывают Orval напрямую.

`AiDialogueQueryFacade.updateDialogue` предоставляет mutation options. Успешный ответ заменяет снимок
конкретного диалога в TanStack Query и соответствующую запись списка; незавершённые чтения этих снимков отменяются,
чтобы старый ответ не затёр сохранённую настройку. Ключи отмены точные: снимок изображений не затрагивается.
При ошибке через `NotificationContext` показывается читаемый текст; прежний выбранный уровень сохраняется.
Подсветка переключается только после подтверждения сервера. Повторный выбор текущего уровня запрос не отправляет.

Пока PATCH выполняется, заблокированы только кнопки переключателя, чтобы не отправлять параллельные изменения.
Форма ответа остаётся доступной: сохранение уровня не блокирует ввод, отправку или завершение диалога.
Если реплика отправлена до завершения PATCH, генератор использует настройку, актуальную на момент чтения диалога.
Изменение уровня разрешено во время генерации NPC: текущий ход после фиксации настроек завершится с прежним уровнем,
следующий использует новый. SSE не переподключается, его формат и сохранённые сообщения не меняются.
Подробная серверная семантика и ограничения адаптации описаны в `aiDialogue.md`.

При создании entity-метод принимает необязательный `cefrLevel`; его выбирают в окне запуска сценария.
Сервер адаптирует все новые видимые тексты на изучаемом языке; переводы сохраняют смысл, озвучка получает адаптированный
текст.

## Разметка страницы

Двухколоночная композиция:

- `AiDialoguePagePartsWrapper` — горизонтальный flex (левая колонка 60 %, правая 40 %). Принимает ровно 2 ребёнка
  `[left, right]`.
- `AiDialogueLeftWrapper` — левая колонка, принимает ровно 2 ребёнка `[messages, input]`: первый — список сообщений (+
  ошибка хода), второй — форма ввода.
- Правая панель — `DetailsBlock` с вкладками «Словарь» (`PhraseDictionary`), «Сообщение» (`AiDialogueMessageReview`) и
  «Настройки» (`AiDialogueSettings`).

Заголовок страницы — `dialogue.scenario.title`, который сервер уже вернул на языке интерфейса (см.
`getHeaderAndSubHeader`).

Тексты интерфейса страницы переведены на 7 языков и лежат в разделах `messages/{locale}/`: `aiDialoguePage`
(загрузка, вкладки правой панели), `aiDialogueForm` (форма ответа), `aiDialogueMessages` (сообщения ленты,
озвучка, иллюстрации), `aiDialogueSettings` (панель настроек), `aiDialogue` (уровень языка, переключатели)
и `dictionary` (Словарь).

### Панель «Сообщение»

Кнопка рядом с именем пользователя показывает суммарное число ошибок и рекомендаций.
Она появляется, когда есть замечания. Нажатие открывает вкладку «Сообщение» и окрашивает кнопку
акцентным цветом. Пока разбор открыт, кнопка недоступна. Клик по слову в ленте открывает «Словарь».

В панели сначала отображается «Реплика», затем «Действие». Для каждой заполненной части показывается
исходный текст, разбор и, если текст изменился, исправленная версия с переводом под ней.
В ленте клик по слову показывает перевод всей реплики или действия. Если замечаний нет, панель
показывает `CheckButtonIcon` справа от исходного текста.

Источник данных разбора — сохранённое событие
`userActions`. [Формат данных](aiDialogueForm.md#данные-для-разбора-ответа-пользователя)

## Клиентские типы (зеркало серверных)

`face/widgets/aiDialogueMessages/types/aiDialogueMessage.ts` — клиентское зеркало
`server/src/types/aiDialogueMessage.ts`:

- `AiDialogueEvent` — union из 6 событий (дискриминатор `type`);
- `AiDialogueClientEvent` — то, что клиент может отправить серверу (`userActions` | `userAvoidsNPC`);
- `DialogueServerMessage` — обёртка сообщения (`id`, `dialogueId`, `createdAt`, `payload`);
- `AiDialogueStreamEvent` — события SSE-потока (`message` / `turnStarted` / `turnDone` /
  `turnError` / `visualsChanged`).

`widgets/aiDialogueMessages/types/aiDialogueUi.ts` — типы выбора слова и обработчика словаря.

## SSE-клиент

`_pages/aiDialogue/AiDialoguePage/fn/openAiDialogueStream.ts` открывает `EventSource('/api/ai-dialogue/:id/stream')` и
разбирает события в стор:

- `message` → `upsertMessage(message)`; новые сообщения текущего хода передаются автоозвучке, replay не озвучивается;
- `turnStarted` → сбросить ошибку и вызвать `setGenerating(true)`: показывается прежний `Waiting for reply`;
- `turnError` → `setTurnError(error)`;
- `turnDone` → `setGenerating(false)`;
- `visualsChanged` и `onopen` → запросить свежий REST-снимок изображений;
- `onerror` → `setGenerating(false)`, снять автоозвучку. Закрытый EventSource переподключается с задержкой от 1 до 15 секунд.

После подключения сервер отдаёт историю и, если фоновая генерация ещё идёт, `turnStarted` для восстановления ожидания.
Чанки и промежуточные попытки генерации клиенту не передаются.

`_pages/aiDialogue/AiDialoguePage/fn/useAiDialogueStream.ts` — хук-обёртка: открывает соединение в `useEffect` (и
закрывает при unmount), при старте
вызывает `clearStore()`, очищает видимость текста реплик и читает настройки «Автоозвучка» и «Текст реплик»
из LocalStorage (до открытия SSE, чтобы первые реплики сразу получили сохранённые значения). Возвращает
`{ messages, turnError }`. Сообщения возвращает
отсортированными по `id`. Второй параметр `enabled` (страница передаёт `Boolean(dialogue)`) — SSE открывается только
после загрузки диалога.

## Zustand-стор (aiDialogueStore)

`_pages/aiDialogue/aiDialogueStore.ts` — глобальный стор страницы:

| Поле           | Тип                                  | Описание                                              |
|----------------|--------------------------------------|-------------------------------------------------------|
| `messages`     | `Map<number, DialogueServerMessage>` | сохранённые сообщения (ключ — `id`, дедуп при replay) |
| `isGenerating` | `boolean`                            | идёт ли генерация ответа NPC                          |
| `turnError`    | `null \| string`                     | текст ошибки последнего хода                          |

Методы: `upsertMessage`, `setGenerating`, `setTurnError`, `clearStore`.

## Рендер сообщений

`AiDialogMessageRouter` выбирает компонент по `event.type` (цепочка `if/else`, не `switch` — `switch` даёт циклический
конфликт `eslint indent` ↔ `prettier`). Принимает только полные сохранённые события.

Компоненты (`ui/messages/`):

- `SceneUpdateMessage` — «Смена сцены»;
- `HelpMessage` — «Подсказка»: рамка `NoticeMessageWrapper` с иконкой, внутри `AiDialogueTextWithTranslation`;
- `WorldEventMessage` — «Событие»: `AiDialogueTextWithTranslation` на сером фоне;
- В подсказке и событии слова кликабельны так же, как в сцене и репликах NPC (`useDialogueContentSelection`),
  но без озвучки и скрытия текста; размер текста 1.6rem.
- `NpcMessage` — аватар, заголовок NPC (имя/роль) + реплики и действия в свойстве `speechAndActions`;
- Внутри всего сообщения NPC сначала показываются все `speech`, затем все `action`, независимо от порядка
  в `payload.actions`. Порядок внутри каждого типа сохраняется. `groupNpcDialogueSpeechAndActions` меняет только порядок
  отображения: ключи React, адреса озвучки и `wordMap.blocks['action:N']` используют исходный индекс `N`.
  Правило общее для новых сообщений и replay. Порядок пользовательских сообщений не меняется.
- У NPC каждый блок имеет аватар 80×80 слева, справа имя/роль и текст; название эмоции не выводится.
  Аватар есть у каждого сообщения, без группировки. Ячейка 240×240 из спрайта обеспечивает запас для Retina.
  Пользовательские `userActions` имеют текущий выбранный аватар профиля и подпись «Вы».
  Изменение профиля обновляет аватар у всех сообщений без истории прежнего выбора.
- `UserMessage` — действия пользователя (без перевода);
- `UserAvoidsNpcMessage` — «Вы отошли от разговора»;
- `PendingAnswerMessage` — плейсхолдер, пока ответ не готов.

Компоненты получают полные сохранённые сообщения.

`AiDialogueMessageList` рисует сохранённые сообщения и `PendingAnswerMessage` при `isGenerating`.
Индикатор `Waiting for reply` показывается от `turnStarted` до `turnDone`, включая повторные попытки генерации.
Сообщения ключуются по `message.id`.

## Изображения на клиенте

`useAiDialogueVisuals` получает авторизованный `/visuals` через существующие Repository → Service → QueryFacade
и сгенерированную Orval-функцию. Снимок хранится отдельно от текстового Zustand в TanStack Query под ключом
`['ai-dialogue', 'detail', dialogueId, 'visuals']`. При обновлении предыдущие данные остаются на экране.

Обновление происходит при открытии страницы, подключении/переподключении SSE, `visualsChanged`, сохранённых
NPC/сценах, возвращении фокуса и восстановлении сети. Сигналы объединяются в окно 250 мс; если запрос уже идёт,
после его завершения выполняется свежее чтение, чтобы не потерять изменения во время получения старого снимка.
При смене диалога снимаются таймеры; старое обновление не затрагивает новую страницу.

Для queued/waitingDependencies/generating снимок проверяется каждые 15 с, после двух минут — 30 с,
после пяти минут — 60 с. Длительный generating не становится failed на клиенте. В скрытой вкладке polling
приостановлен. Когда незавершённых заданий нет, опрос останавливается; ошибки REST повторно проверяются через минуту.
Текстовый ход и доступность формы не зависят от загрузки изображений.

`DialogueVisualsProvider` индексирует NPC по npcId, сцены по messageId и перечитывает visuals
при смене avatarUrl в UserProvider. `DialogueAvatar` вырезает нужную ячейку
раскладки emotion-grid-4x3-v1; неизвестная эмоция использует neutral. Неизвестная или неподходящая геометрия
спрайта оставляет серую заглушку. Файл спрайта общий для всех реплик NPC, параллельные загрузки объединяются.

В `SceneUpdateMessage` иллюстрация находится **над текстом**, занимает всю ширину и сохраняет пропорции 2:1.
Увеличения по нажатию нет. Серый слот без надписей резервируется для новых сцен
с visualDescription. У старой сцены без задания/изображения слот отсутствует; уже показанный слот не схлопывается.
Сцены загружаются при приближении к видимой области. Подготовка аватаров также показывает только серую область.

Новый подписанный URL сначала загружается/декодируется, затем заменяет отображаемый. Ошибка скачивания вызывает
не больше одного автоматического обновления ссылок на ассет за время открытия диалога. Ошибка сцены оставляет
слот и показывает «Иллюстрация недоступна»; при ошибке скачивания доступна «Повторить загрузку».
Кнопка повторяет только чтение снимка/скачивание, не генерацию. Ошибка аватара оставляет серую заглушку.
Изображения не вызывают программную прокрутку или перемонтирование текстовых блоков с раскрытым переводом.

Технические поля participants:/visual: разбираются сервером и не попадают в текст сообщения.

Клиентские тесты: `cd face && npm run test:ai-dialogue` (EventSource/Image подменены).

## Выбор словарной фразы (SegmentedText)

`SegmentedText` — обёртка над общим кликабельным текстом `ClickableText` (`documentation/topics/clickableText.md`):
рамка при наведении, затухание, заливка выбранных слов и касания описаны там. Здесь — что выбирается в диалоге.

Карта генерируется в конце основного ответа LLM (`aiDialogueWordMaps.md`) и приходит внутри SSE message.
SegmentedText делит текст по позициям готовой карты (`splitDialogueText`), сохраняя пробелы и пунктуацию текста.
Клик сразу передаёт phrase из записи для нажатого слова или само слово при отсутствии записи/карты.
Ожидания и автоматической подмены словарного запроса после появления карты нет.

Рамка при наведении и заливка после клика охватывают ровно те слова, которые уйдут в Словарь: все `wordIds`
собственной записи слова (в том числе несмежные, `put … away`) или только само слово без карты/записи
(`getHighlightedWordStarts`). У всех слов группы запись одинаковая: в `Plenty of people` наведение и на Plenty,
и на of подсвечивает `Plenty of`. Выбор один на страницу: `useSelectedWordsStore` хранит id экземпляра
SegmentedText (`useId`) и начала слов, вычисленные в момент клика (`useSegmentedTextSelection`). Клик по слову
в другом тексте переносит заливку туда, смена диалога её снимает.
Для put … away словарь получает put away; для Do you have клик по Do, you или have выбирает всю конструкцию.
Превью также допускает клики с немедленным запасным выбором слова.
Пользовательские сообщения всегда выбирают отдельное слово.
Должность NPC в заголовке (`NpcRoleText`) — тот же SegmentedText с картой `buildWholeTextWordMap`: вся должность —
одно выражение, поэтому наведение на любое её слово обводит её общей рамкой, а клик отправляет её целиком
(`music shop assistant`). Перевода у должности нет. `WithAvatarMessageWrapper` принимает `role` как ReactNode.
AiDialogueContentBlock, HelpMessage и WorldEventMessage раскрывают существующий перевод всего блока, передаёт
phrase/слово в поле word
и content в поле sentence. Правая панель не передаёт sentence в словарь.
Технический раздел wordMaps: разбирается сервером и не показывается пользователю.

## Форма ответа пользователя

`AiDialogueInput.tsx` показывает вкладки «Реплика» и «Действие», растущий редактор,
кнопку ухода, диктовку и отправку. Пользователь может отправить одну или обе заполненные части.
При ошибке черновики остаются в форме. После успешной отправки хук `useAiDialogueSendMessage`
добавляет подтверждённый ход из REST в ленту.

Диктовка использует отдельный WebSocket `/api/ai-dialogue/:id/dictation` и вставляет распознанный
текст в сохранённое положение курсора или выделение. Во время записи редактор доступен для чтения.

При исчерпанном балансе отображается `BalanceExhaustedNotice`. После начисления форма возвращается
с черновиками текущего диалога. [Обновление баланса](../topics/billing.md#баланс-в-реальном-времени)

[Форма ответа](aiDialogueForm.md) · [Контракт диктовки](aiDialogueDictation.md)

### Entity-метод createMessage

`createMessage(id, event: AiDialogueClientEvent): Promise<ApiResult<DialogueServerMessage>>` проходит цепочку
`AiDialogueRepository` → `AiDialogueApi` (через сгенерированный `aiDialogueControllerCreateAiDialogueMessage`
и маппинг `AiDialogueMessageOutModel` → `DialogueServerMessage`) → `AiDialogueService`.

## Ошибки

- Ошибка хода приходит событием `turnError`; читаемый текст резолвится в
  `_pages/aiDialogue/AiDialoguePage/fn/resolveTurnError.ts`
  (JSON `{"code": "..."}` → `resolveErrorByCode`, иначе строка как есть). Показывается над списком сообщений
  (`ErrorMessage`).
- Попытка отправить сообщение во время генерации → `400 AI_DIALOGUE_GENERATION_ALREADY_ACTIVE`; клиент упреждающе
  блокирует форму по `isGenerating`.
- Ошибки отправки показываются через `notify` (`NotificationContext`).

## Настройки реплик

В панели `AiDialogueSettings` под уровнем языка два переключателя (`AutoVoiceToggle` и `ReplyTextToggle`, компонент
`Toggle`):
«Автоозвучка» и «Текст реплик». Значения хранятся в LocalStorage (`localStorageManager.aiDialogueReplySettings`),
по умолчанию оба включены, и действуют только на будущие реплики. Подписи — `aiDialogue.replySettings`
в `messages/*/aiDialogue.json`.

### Текст реплик

Правило касается реплик NPC и описаний сцен; невербальные действия видны всегда.

- Реплика получает видимость по текущему значению переключателя, когда появляется на экране, и дальше от него
  не зависит. Видимость хранится в памяти (`replyTextVisibilityStore`), пока открыта страница.
- Скрытый текст заменяет кнопка с первыми символами и многоточием («You've…»). Её нет, пока текст ещё не пришёл.
  Нажатие открывает текст; обратно он не скрывается.
- При открытии или перезагрузке страницы все реплики показаны или скрыты по значению из LocalStorage:
  какие реплики открывались вручную, не запоминается.
- Ключ видимости — `${messageId}:${actionIndex}` (`actionIndex = -1` у сцены).

### Озвучка

Кнопка воспроизведения есть у каждой сохранённой реплики и описания сцены. Кнопка воспроизведения, кнопка
скрытого текста и сам текст лежат в одной строке `AiDialogueContentBlock` (`__line`): кнопки — inline-block
в начале первой строки текста, перевод — отдельным абзацем ниже. Поэтому кнопки стоят на одной высоте
и при видимом, и при скрытом тексте.
При включённой «Автоозвучке» новый ответ озвучивается сам; при выключенной — только по нажатию.
При запрете autoplay браузером показывается «Включить звук».
Запросы, порядок и ошибки: [`aiDialogueAudio.md`](aiDialogueAudio.md).

## Интерфейс экзамена

`DialogueModeContext` задаёт режим всему дереву сообщений. В экзамене `AiDialoguePage` сохраняет `ViewportSyncedHeight` и `DetailsBlock` с пустым массивом `tabs` (компонент возвращает `null`, если вкладок нет): отсутствуют «Словарь», «Сообщение» и «Настройки». Панель прохождения пока не реализована.
Речь NPC и описание сцены показывают только кнопку озвучки: текста, буквенного превью и раскрытия нет.
Действия и другие видимые текстовые события отображаются обычным текстом без слов-кнопок и перевода;
`help` не отображается. Исходный ответ пользователя не получает кнопку разбора.
Страница задаёт политику автоозвучки: в экзамене она всегда включена, в практике читается сохранённая настройка.
Проигрыватель не получает режим диалога: `useAiDialogueAudio` принимает функцию `shouldAutoplay`,
вызываемую при получении сообщения. Настройка практики не перезаписывается. Кнопка позволяет
повторять прослушивание и загрузку после ошибки.

`SegmentedText` не знает режим диалога. Родители выбирают его для практики и обычный текст для экзамена.

### Кнопка проверки и отчёт

`AiDialogueExamSubmission` расположен после списка сообщений только в экзамене. `getExamProgress`
считает отправки с непустой репликой, ограничивает остаток снизу нулём и находит сохранённый `examResult`.
Подписи кнопки и отчёта локализованы на семи языках, русская подпись учитывает число оставшихся ответов.
Кнопка недоступна до клиентского порога `EXAM_MIN_REPLIES`, при генерации NPC, проверке и исчерпанном балансе. Сервер количество ответов не проверяет.
Во время HTTP-проверки форма ответа остаётся видимой, но заблокирована.
При ошибке показывается сообщение и разрешается повтор. При успешном результате событие попадает в стор;
кнопка и форма вместе с её обёрткой исчезают, на месте кнопки отображается отчёт.
SSE-replay после перезагрузки восстанавливает этот же результат и завершённое состояние интерфейса.
Боковые вкладки экзамена остаются пустыми. Медали в отчёте не отображаются.
