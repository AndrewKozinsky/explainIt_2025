# Хранение файлов

Эти правила применяются ко всем серверным функциям, которые создают, загружают, читают или удаляют файлы,
включая HTTP-сервер, воркеры и скрипты начального заполнения.

## Разделение по сайтам

| Сайт | Регион | Хранилище серверных файлов |
|---|---|---|
| `immersia.site` | `intl` | Cloudflare R2, приватный бакет `immersia-private` |
| `explainit.ru` | `ru` | Отдельное S3-совместимое хранилище. Подключение запланировано |

Cloudflare R2 предназначен для `immersia.site`. При работе над `explainit.ru` используйте отдельное хранилище
и отдельные учётные данные. В текущей реализации сервер использует `CloudflareS3Service` без выбора провайдера
по `REGION`. Имя приватного бакета задаётся переменной `CLOUDFLARE_S3_BUCKET_NAME`.

Публичная статика `immersia.site` размещается отдельно в бакете `immersia-public` и доступна через
`https://files.immersia.site/`. Её адреса собраны в `face/shared/utils/filesUrls.ts`.
Медали сценариев также хранятся в `immersia-public`: `ai-dialogue-scenario-medals/<MODE>/<scenarioSlug>/<LEVEL>.webp`.
Сервер формирует постоянные ссылки через `getPublicFileUrl` в `infrastructure/cloudflareS3/publicFileUrl.ts`;
подпись и запрос к S3 не требуются. Для каждого сценария предусмотрены отдельные пять файлов A1–C1.

## Разделение по окружениям

Для ключей серверных файлов, которые строит приложение, используйте фактическое значение `MODE` без подмены
на другое окружение. Общий формат ключа — `<категория>/<MODE>/<путь к файлу>`. Если в существующей категории
используется регион, он входит в путь категории перед `MODE`. Новые категории именуются строчными буквами
с дефисами между словами.

| Файл | Ключ внутри `immersia-private` |
|---|---|
| Готовый аватар для локальной разработки | `user-avatars-shared/localdev/male-1.jpg` |
| Тот же аватар для опубликованной версии | `user-avatars-shared/servermaster/male-1.jpg` |
| Пользовательская фотография | `user-avatars/uploads/<REGION>/<MODE>/<userId>/<uuid>.webp` |
| Обложка публичной книги | `public-books-covers/<MODE>/<язык>/<имя файла>` |

Для построения префикса сервер использует `getR2EnvironmentPrefix` из
`server/src/infrastructure/cloudflareS3/r2EnvironmentPrefix.ts`. Имя окружения начинается с латинской буквы
или цифры и может содержать латинские буквы, цифры, `-` и `_`. У функции нет списка фиксированных окружений.

HTTP-сервер и воркеры одного окружения используют одинаковые `REGION`, `MODE` и настройки хранилища.
Если очистка проверяет наличие ссылок на файлы в БД, каждому обслуживаемому префиксу должна соответствовать
одна БД. При обходе хранилища очистка ограничивается префиксом своего окружения.

## Существующие ключи и смена окружения

БД и задания очереди хранят полные ключи объектов. Новые записи и задания формируют ключи по текущей схеме путей.
После удаления старых папок ссылки на них в существующих записях и заданиях перестают работать.

Перед запуском нового или переименованного окружения разместите ресурсы, которые сервер ищет по вычисляемым
ключам, под соответствующим `MODE`. Это готовые аватары, стили и превью ИИ-диалогов, обложки публичных сценариев
и обложки публичных книг.

При смене структуры хранения переведите на новые префиксы все компоненты приложения. После выкладки обновлённого
кода для всех типов файлов старые папки можно удалить. Готовые ресурсы, нужные приложению, должны быть доступны
по новым ключам к моменту выкладки.

## Подписанные ссылки R2

`CloudflareS3Service.getFileUrl` округляет время подписи GET-ссылки до начала шестичасового окна
`signedFileUrlWindowSeconds`. Ссылка действует два окна, поэтому при выдаче до истечения остаётся не меньше шести
часов. Ответ R2 содержит `Cache-Control: private` с тем же сроком. В пределах окна повторные ответы API выдают
одинаковую ссылку. Замена файла по тому же ключу становится видна со следующего окна.

Клиент получает свежую ссылку при следующем запросе данных. Срок действия отдельно не передаётся, обновления
по таймеру нет.
