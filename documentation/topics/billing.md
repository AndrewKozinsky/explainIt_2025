# Баланс и тарифы

Баланс ограничивает расходы на ИИ: каждый пользователь получает дневную сумму, а каждый запрос к ИИ списывает с неё
реальную стоимость по ценам поставщика, без наценки. Когда баланс исчерпан, запросы к ИИ не выполняются до следующего
начисления, а интерфейс показывает сообщение о дневном лимите со ссылкой на тарифы.

Тарифы только показываются: оплаты на сайте нет. Они нужны, чтобы ограничить бесконечное использование ИИ и оценить
интерес к платной версии.

## Страница тарифов

`/pricing` (`pageUrls.pricing`, `face/_pages/pricing/PricingPage/`) сравнивает два тарифа. Возможности у них одинаковые,
отличается только дневной лимит на ИИ; слово «безлимит» нигде не используется.

| | Бесплатно | Подписка |
|---|---|---|
| Дневной лимит | небольшой | в 10 раз больше |
| Неистраченный лимит | не переносится на следующий день | переносится на следующий день |
| Срок | — | 30 дней без автопродления |
| Цена | — | $15 |

Под тарифами — время обновления лимита в часовом поясе браузера и правило превышения, ниже — что происходит после
окончания подписки. Кратность лимита, срок и цена — `face/shared/consts/pricingConfig.ts`; эти же значения использует
сообщение о лимите. Ежедневное начисление на сервере их не использует: тарифы пока не влияют на баланс. Кнопка
«Выбрать» пока ничего не делает. Тексты — `messages/{locale}/pricingPage.json`.

## Единицы

Баланс (`User.balance`) и все суммы внутри сервера хранятся в **микродолларах** — целых миллионных долях доллара.
Цент слишком крупный: запрос к LLM стоит доли цента, а дробные доллары в JS накапливают ошибки округления.
Поставщики ИИ выставляют цены в долларах, поэтому баланс тоже в долларах, независимо от региона.

Перевод — `server/src/utils/microdollars.ts`:

| Функция | Назначение |
|---|---|
| `dollarsToMicrodollars` | суммы из конфигурации (округление до ближайшего) |
| `microdollarsToDollars` | обратный перевод |
| `costInDollarsToMicrodollarsCharge` | стоимость запроса → сумма списания (округление вверх, чтобы списание не было меньше расходов) |

## Ежедневное начисление

`RefillFreeDailyBalance` (`server/src/features/billing/RefillFreeDailyBalance.service.ts`) каждый день в 00:00 UTC
одним SQL-запросом (`UserRepository.increaseBalanceOfAllUsers`) прибавляет к балансу всех пользователей дневную сумму
`billing.freeDailyBalanceInDollars` из `mainConfig`, но не даёт итогу превысить её:

- минус учитывается: −2 ¢ → 8 ¢;
- неизрасходованный остаток не копится: 5 ¢ → 10 ¢.

Новый пользователь получает ту же сумму при регистрации (по почте и через OAuth).

Модуль `DailyBalanceRefillModule` подключён только в `AppModule`: в worker расписания нет, иначе начисление шло бы
дважды. Расписание рассчитано на один экземпляр сервера в регионе.

Начисление одно для всех: тарифы пока не влияют на баланс. Сумма живёт в `mainConfig`.

## Проверка и списание

`UserBalanceService` (`server/src/features/billing/UserBalance.service.ts`) — единая точка для всех запросов к ИИ.
`BillingModule` глобальный и подключён в `AppModule` и `WorkerModule`.

- **Перед запросом** `ensurePositiveBalanceOrThrow(userId, feature)`: если баланс не больше нуля, бросает
  `CustomError` с кодом `BALANCE_EXHAUSTED` и HTTP-статусом 402. По этому коду клиент показывает объяснение, что
  делать дальше. Для фоновых работ без ошибки — `hasPositiveBalance(userId)`.
- **После ответа** `chargeLlm`, `chargeImageGeneration`, `chargeOpenAiTts`, `chargeSpeechToText` считают стоимость
  и атомарно уменьшают баланс (`UserRepository.decreaseBalance`).

Стоимость потокового ответа известна только после него, поэтому последний запрос может увести баланс в минус. Ответ
не обрывается. Минус вычитается из следующего начисления. Ошибка списания пишется в лог и не ломает ответ
пользователю.

### Где списывается

Списывается только то, что ИИ делает лично для пользователя. Владелец диалога, чата, личной книги или видео платит
за свои запросы.

| Функция | Проверка перед запросом | Списание |
|---|---|---|
| Создание диалога, действие пользователя | 402 | — |
| Ход NPC (`GenerateAiDialogueTurn`) | `turnError` с кодом `BALANCE_EXHAUSTED` в SSE | токены каждой попытки (попытка с неразобранным ответом тоже оплачена поставщиком) |
| Сводка диалога (`SummarizeAiDialogue`) | без баланса откладывается молча | токены |
| Проверка черновика | 402 | токены |
| Озвучка реплики | 402; готовая озвучка отдаётся без проверки | текст по символам, аудио по длительности MP3 |
| Картинки диалога (worker) | без баланса задание завершается ошибкой, запрос поставщику не отправляется | токены из ответа OpenAI |
| Диктовка | WebSocket отклоняется с 402 и кодом в теле | время открытого потока Soniox |
| Перевод фраз и предложений | 402, только личные книги и видео | токены |
| Чат по предложению | ошибка в SSE | токены |
| Субтитры личного видео | 402 | длительность аудио в Deepgram |

Бесплатно, без проверки и списания: словарные статьи и их обогащение, картинки значений слов, транскрипции,
переводы в публичных книгах и видео, субтитры YouTube-видео, обложки сценариев. Это общий кэш: его используют все
пользователи, поэтому он не списывается с того, кто случайно запросил его первым.

Двухчасовое видео стоит около $0.52 распознавания — больше дневной суммы. Списание проходит целиком, и пользователь
несколько дней не сможет пользоваться ИИ, пока минус не погасится начислениями.

## Баланс в реальном времени

Клиент узнаёт актуальный баланс без перезагрузки страницы через личный SSE-поток `GET /api/user/events`
(`UserController.events`, нужна сессия). Поток отдаёт одно событие `{ type: 'balance', balance }` — баланс в
микродолларах, может быть отрицательным:

- сразу после подключения — текущее значение из БД;
- после каждого списания;
- после ежедневного начисления.

Тип события — `server/src/types/userStreamEvent.ts`, его клиентское зеркало — `face/entities/user/types/userStreamEvent.ts`.

### Сервер

Списания идут и в HTTP-процессе, и в worker, а SSE-потоки открыты только в HTTP-процессе. Поэтому изменения
передаются через Redis Pub/Sub, а не подпиской на БД:

1. `UserBalanceService` после `decreaseBalance` публикует `userBalanceChanged` с новым балансом пользователя.
   Публикация без ожидания: недоступный Redis не задерживает ответ.
2. `RefillFreeDailyBalance` после начисления публикует `allBalancesChanged` без сумм.
3. `UserBalanceEvents` в HTTP-процессе получает уведомления. Новый баланс одного пользователя он передаёт в его потоки
   как есть. На `allBalancesChanged` одним запросом (`UserRepository.getBalancesOfUsers`) читает балансы подключённых
   пользователей этого процесса и отправляет каждому его значение. То же он делает после переподключения к Redis:
   уведомления за время разрыва потеряны.
4. `UserEventsSseHub` хранит потоки по пользователям; у пользователя может быть несколько вкладок.
5. `OpenUserEventsStreamHandler` подписывает поток на шину до чтения баланса из БД. Если во время чтения пришло
   событие, прочитанное значение не отправляется: событие новее.

Канал Redis — `user-balance:{MODE}:{region}` (`UserBalanceNotifications`). Общая логика каналов уведомлений —
`RedisNotificationChannel`; её же использует `AiDialogueVisualNotifications`. Доставка не гарантирована: при
сбое клиент получит верный баланс при следующем изменении или переподключении потока.

### Клиент

`UserProvider` для вошедшего пользователя открывает поток (`face/entities/user/events/openUserEventsStream.ts`) и
обновляет `balance` в контексте и кэше `['user', 'me']`. Поток зависит только от id пользователя, поэтому новый баланс
не переоткрывает соединение. EventSource сам переподключается при обрыве.

Если поток отстал, а сервер ответил 402, `customMutator` подаёт сигнал (`shared/api/balanceExhaustedSignal.ts`), и
`UserProvider` локально делает баланс не больше нуля. Точное значение приходит следующим событием потока.

`useIsBalanceExhausted()` (`face/entities/user/fn/`) возвращает true, если пользователь вошёл и баланс не больше нуля.
Пока лимит исчерпан:

| Место | Что видит пользователь |
|---|---|
| Окно запуска сценария (`StartDialogueModal`) | сообщение о лимите вместо кнопки «Начать диалог» |
| Страница диалога | сообщение о лимите вместо формы ответа; черновик не сохраняется |
| Кнопки озвучки диалога | неактивны, подсказка «Озвучка недоступна»; играющую озвучку можно остановить |
| Чат о предложении | сообщение о лимите над полем ввода |

После начисления всё возвращается само, без перезагрузки.

`BalanceExhaustedNotice` (`face/entities/user/ui/BalanceExhaustedNotice/`) — сообщение о лимите. Оно само скрывается при
положительном балансе. Время обновления лимита — ближайшие 00:00 UTC в часовом поясе браузера, со словом «сегодня»
или «завтра». При серверном рендере время не выводится: часовой пояс сервера другой. Кнопка «Посмотреть тарифы»
ведёт на `pageUrls.pricing` и отправляет в PostHog `pricing_link_clicked` со свойством `placement`
([posthog.md](posthog.md)). Тексты — `messages/{locale}/balanceExhaustedNotice.json`.

## Цены и расчёт стоимости

Цены поставщиков — в `mainConfig` (`server/src/infrastructure/mainConfig/mainConfig.service.ts`), в долларах.
Рядом с каждой ценой указан источник и дата проверки. Берётся полная цена: акционные цены и цены вне пиковых часов
не учитываются.

Расчёт — чистые функции в `server/src/features/billing/aiUsageCost.ts`:

| Поставщик | Как считается |
|---|---|
| LLM (DeepSeek, OpenAI, z.ai, MiMo, Gemini) | входные токены, кэшированные входные токены и выходные токены — по своим ценам за 1M; OpenAI с `lowPriority` (flex) — вдвое дешевле |
| Картинки OpenAI | текст, референсы и картинка на выходе — по токенам из поля `usage` ответа |
| Картинки FLUX 3 | цена за картинку по ярусу размера; если OpenAI не вернул токены, картинка оценивается так же |
| Озвучка OpenAI | API не сообщает токены: текст оценивается по числу символов, аудио — по длительности MP3 (`mp3Frames.ts`) |
| Soniox, Deepgram | цена за минуту аудио |

Провайдеры LLM сообщают кэшированные токены (`LlmTokenUsage.cachedInputTokens`), а `LlmAdapterService.generate`
возвращает модель, которая ответила: по ним считается стоимость.

## Аналитика

`PosthogService` отправляет события баланса (см. [posthog.md](posthog.md)):

- `balance_exhausted` — списание перевело баланс из плюса в ноль или минус;
- `ai_request_blocked_by_balance` — запрос к ИИ отклонён из-за баланса.

Свойство `feature` — функция из `server/src/types/billableAiFeature.ts`.
