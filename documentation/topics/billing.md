# Баланс и оплата

Оплаты на сайте нет. Баланс ограничивает расходы на ИИ: каждый пользователь получает дневную сумму, а каждый запрос к
ИИ списывает с неё реальную стоимость по ценам поставщика, без наценки. Когда баланс исчерпан, запросы к ИИ не
выполняются до следующего начисления.

## Единицы

Баланс (`User.balance`) и все суммы внутри сервера хранятся в **микродолларах** — целых миллионных долях доллара.
Цент слишком крупный: запрос к LLM стоит доли цента, а дробные доллары в JS накапливают ошибки округления.
Поставщики ИИ выставляют цены в долларах, поэтому баланс тоже в долларах, независимо от региона.

Перевод — `server/src/utils/microdollars.ts`:

| Функция | Назначение |
|---|---|
| `dollarsToMicrodollars` | суммы из конфигурации (округление до ближайшего) |
| `microdollarsToDollars` | обратный перевод |
| `costInDollarsToMicrodollarsCharge` | стоимость запроса → сумма списания (округление вверх, чтобы списание не было меньше расходов) |

## Ежедневное начисление

`RefillFreeDailyBalance` (`server/src/features/billing/RefillFreeDailyBalance.service.ts`) каждый день в 00:00 UTC
одним SQL-запросом (`UserRepository.increaseBalanceOfAllUsers`) прибавляет к балансу всех пользователей дневную сумму
`billing.freeDailyBalanceInDollars` из `mainConfig`, но не даёт итогу превысить её:

- минус учитывается: −2 ¢ → 8 ¢;
- неизрасходованный остаток не копится: 5 ¢ → 10 ¢.

Новый пользователь получает ту же сумму при регистрации (по почте и через OAuth).

Модуль `DailyBalanceRefillModule` подключён только в `AppModule`: в worker расписания нет, иначе начисление шло бы
дважды. Расписание рассчитано на один экземпляр сервера в регионе.

Платных тарифов пока нет: начисление одно для всех. Сумма живёт в `mainConfig`, позже она переедет в тарифы.

## Проверка и списание

`UserBalanceService` (`server/src/features/billing/UserBalance.service.ts`) — единая точка для всех запросов к ИИ.
`BillingModule` глобальный и подключён в `AppModule` и `WorkerModule`.

- **Перед запросом** `ensurePositiveBalanceOrThrow(userId, feature)`: если баланс не больше нуля, бросает
  `CustomError` с кодом `BALANCE_EXHAUSTED` и HTTP-статусом 402. По этому коду клиент показывает объяснение, что
  делать дальше. Для фоновых работ без ошибки — `hasPositiveBalance(userId)`.
- **После ответа** `chargeLlm`, `chargeImageGeneration`, `chargeOpenAiTts`, `chargeSpeechToText` считают стоимость
  и атомарно уменьшают баланс (`UserRepository.decreaseBalance`).

Стоимость потокового ответа известна только после него, поэтому последний запрос может увести баланс в минус. Ответ
не обрывается. Минус вычитается из следующего начисления. Ошибка списания пишется в лог и не ломает ответ
пользователю.

### Где списывается

Списывается только то, что ИИ делает лично для пользователя. Владелец диалога, чата, личной книги или видео платит
за свои запросы.

| Функция | Проверка перед запросом | Списание |
|---|---|---|
| Создание диалога, действие пользователя | 402 | — |
| Ход NPC (`GenerateAiDialogueTurn`) | `turnError` с кодом `BALANCE_EXHAUSTED` в SSE | токены каждой попытки (попытка с неразобранным ответом тоже оплачена поставщиком) |
| Сводка диалога (`SummarizeAiDialogue`) | без баланса откладывается молча | токены |
| Проверка черновика | 402 | токены |
| Озвучка реплики | 402; готовая озвучка отдаётся без проверки | текст по символам, аудио по длительности MP3 |
| Картинки диалога (worker) | без баланса задание завершается ошибкой, запрос поставщику не отправляется | токены из ответа OpenAI |
| Диктовка | WebSocket отклоняется с 402 и кодом в теле | время открытого потока Soniox |
| Перевод фраз и предложений | 402, только личные книги и видео | токены |
| Чат по предложению | ошибка в SSE | токены |
| Субтитры личного видео | 402 | длительность аудио в Deepgram |

Бесплатно, без проверки и списания: словарные статьи и их обогащение, картинки значений слов, транскрипции,
переводы в публичных книгах и видео, субтитры YouTube-видео, обложки сценариев. Это общий кэш: его используют все
пользователи, поэтому он не списывается с того, кто случайно запросил его первым.

Двухчасовое видео стоит около $0.52 распознавания — больше дневной суммы. Списание проходит целиком, и пользователь
несколько дней не сможет пользоваться ИИ, пока минус не погасится начислениями.

## Цены и расчёт стоимости

Цены поставщиков — в `mainConfig` (`server/src/infrastructure/mainConfig/mainConfig.service.ts`), в долларах.
Рядом с каждой ценой указан источник и дата проверки. Берётся полная цена: акционные цены и цены вне пиковых часов
не учитываются.

Расчёт — чистые функции в `server/src/features/billing/aiUsageCost.ts`:

| Поставщик | Как считается |
|---|---|
| LLM (DeepSeek, OpenAI, z.ai, MiMo, Gemini) | входные токены, кэшированные входные токены и выходные токены — по своим ценам за 1M; OpenAI с `lowPriority` (flex) — вдвое дешевле |
| Картинки OpenAI | текст, референсы и картинка на выходе — по токенам из поля `usage` ответа |
| Картинки FLUX 3 | цена за картинку по ярусу размера; если OpenAI не вернул токены, картинка оценивается так же |
| Озвучка OpenAI | API не сообщает токены: текст оценивается по числу символов, аудио — по длительности MP3 (`mp3Frames.ts`) |
| Soniox, Deepgram | цена за минуту аудио |

Провайдеры LLM сообщают кэшированные токены (`LlmTokenUsage.cachedInputTokens`), а `LlmAdapterService.generate`
возвращает модель, которая ответила: по ним считается стоимость.

## Аналитика

`PosthogService` отправляет события баланса (см. [posthog.md](posthog.md)):

- `balance_exhausted` — списание перевело баланс из плюса в ноль или минус;
- `ai_request_blocked_by_balance` — запрос к ИИ отклонён из-за баланса.

Свойство `feature` — функция из `server/src/types/billableAiFeature.ts`.

## Оплата через ЮKassa

Код пополнения баланса через ЮKassa сохранён на будущее, но отключён:

- модули `PaymentModule`, `YooKassaModule`, `WebhookModule` не подключены в `AppModule`;
- файлы ЮKassa исключены из компиляции в `server/tsconfig.json` и `server/tsconfig.build.json` (`infrastructure/yooKassa`,
  `features/payment`, `routes/payment`, `routes/webhook`, `models/payment`, `repo/payment.repository.ts`,
  `repo/userBalanceTransaction.repository.ts`).

Таблиц `Payment` и `UserBalanceTransaction` в базе нет. Чтобы вернуть ЮKassa, нужно восстановить их в `dbConfig.ts`
и перевести код на микродоллары.
